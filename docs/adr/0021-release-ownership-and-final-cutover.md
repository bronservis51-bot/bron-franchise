# ADR-0021: сопровождение релиза и окончание зарубежной записи

Дата: 10.11.2026. Статус: принято для подготовки; реализация не завершена.
Уточняет ADR-0010 и заменяет допущение ADR-0014 о бессрочном зарубежном приёмнике
старых анкет после локализации. Архитектура приложения сохраняется.

Владелец не технический специалист. Ежедневное обслуживание, разбор тревог и
восстановление должны выполнять назначенные специалисты. До оплаты нужны состав
сопровождения именно Docker/Supabase/PostgreSQL, копий и восстановления, срок
реакции и полная цена. Общая поддержка VPS этого не доказывает; помощь разработчика
или ИИ по обращению не является круглосуточным дежурством.

Мост поздних заявок защищает UUID и работу менеджера. Продолжение первичного сбора
в зарубежной базе не завершает выбранную локализацию. У старого лендинга API США
записан в HTML; DNS не изменяет код уже открытой вкладки.

Перед переносом определяем момент T: после него новые клиентские записи идут
только в российскую систему. До T подготавливаем обе сборки, отправку/сохранение
origin-очередей, перенос открытых смен, финальную сверку и проверенное ограничение
старых команд. Сначала действующий российский приёмник, затем прекращение старой
записи и финальная дозагрузка уже принятых UUID. `migration:leads` не разрешает
бессрочно принимать новые персональные данные в зарубежную БД.

Нельзя обещать, что очень старая загруженная анкета без обновления сама сменит API.
Способ восстановления ввода и остаточный риск обращения к старому адресу проверяются
отдельно; скрытое продолжение зарубежного приёма не является решением. Прекращение
вставок в старую БД само по себе не доказывает отсутствие зарубежных передач.

После T исходник временно сохраняется закрытым для сверки и восстановления по
утверждённому порядку хранения. После первых новых записей на цели откат требует
обратной сверки; одного возврата DNS недостаточно. Закрытие GitHub-репозитория
выполняется после проверки старых PWA/очередей и обращений к публичному GitHub API.
Не отключать старый Pages раньше готового способа восстановления очереди.

Допуск — по [критериям релиза](../release-gates.md). Этот ADR не означает, что
обслуживание заказано, перенос выполнен, очереди обработаны или документы оператора
ПД утверждены.

Источники: [ст. 18 152-ФЗ](https://mintrud.gov.ru/docs/laws/130),
[self-hosting Supabase](https://supabase.com/docs/guides/self-hosting),
[перенос](https://supabase.com/docs/guides/self-hosting/restore-from-platform).
