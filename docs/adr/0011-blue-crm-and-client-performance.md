# ADR-0011 Синий акцент, канбан заявок и загрузка PWA

Статус: принято, 2026-11-04.

## Контекст

Нужны выразительный интерфейс, меньшая нагрузка на сеть и привычная CRM с
квалификацией по бюджету, помещению и близости открытия. Приём анкет отдельным
лендингом и существующие статусы/заметки должны сохраняться.

## Решение

- Монохромный логотип, серебро и Montserrat сохраняются по брендбуку. Синий
  `#2F5CFF` / `#1B3FD6` взят из текущего `bronservice-franchise`, а не объявлен
  цветом из PDF-брендбука. Используется в действиях, активной навигации, плане,
  экране входа, CRM и цвете оболочки PWA; есть светлая и тёмная темы.
- Новые заявки группируются по точным ответам: `budget=full`, `place=has`,
  `timing=month`. Частичная сумма, варианты места и срок от 1–3 месяцев не равны
  полной готовности. Все восемь комбинаций представлены отдельно.
- Порядок: нет подтверждённых условий → только помещение → только сейчас →
  только деньги → помещение и сейчас → деньги и помещение → деньги и сейчас →
  все три → в работе → договор → отказ. Сначала число положительных условий;
  при равенстве приоритет бюджету, затем близости открытия.
- `call_back`, `meeting`, `in_work` показаны в «В работе» с точным статусом на
  карточке. Ручной статус имеет приоритет над квалификацией. Возврат в `new`
  снова распределяет по анкете. Это сегменты, а не обязательные линейные шаги.
- Перетаскивание меняет рабочий статус через прежний `lead_update`. Между
  квалификационными колонками вручную не перетаскивают: они отражают ответы
  человека. На телефоне и с клавиатуры доступен выбор статуса в карточке.
  Поля анкеты не переписываются, SQL и `lead_submit` не меняются.
- Поля формы не сбрасываются фоновым обновлением; известная смена версии заявки
  блокирует сохранение. Это клиентская защита, а не атомарный контроль версии:
  текущий серверный `lead_update` не принимает `expected_version`.
- Главная франчайзи загружается отдельно. Общие компоненты месяца вынесены из
  неё, чтобы просмотр других разделов не импортировал весь кабинет. React и
  backend-библиотеки имеют отдельные стабильные кешируемые файлы.
- Montserrat ограничен кириллицей и латиницей; остальные символы доступны через
  системный шрифт. Кеш запросов в памяти: свежесть 60 секунд, хранение 30 минут.
  Существующие invalidation после записей сохранены. Счётчик CRM не опрашивается
  отдельно, пока открыт полный список; он берётся из этого списка.
- PWA регистрируется после `load` в свободное время (до 5 секунд ожидания).
  Проверка обновлений в закрытой вкладке/без сети пропускается. API и файлы
  пользователей service worker по-прежнему не кеширует; очередь не очищается.
  Активный native dialog также блокирует применение обновления.
- Сбой фонового обновления оставляет загруженные данные с явным предупреждением.
  При отказе авторизации/доступа вместо них показывается ошибка.

## Проверка и ограничения

Unit-тесты покрывают все 36 ответов анкеты, порядок сегментов, рабочие статусы,
локальный поиск и сохранение старого экрана при сетевом сбое. Права и SQL —
существующие тесты PGlite. UI проверяется на синтетических данных без записей
в рабочую очередь, на desktop и ширине 390px. Отдельно проверять production
сборку, CI, Pages и необходимость обновить установленную PWA.

Уменьшение файлов не равно измеренному ускорению на каждом устройстве. Время
первого чтения и сохранения зависит от сети и текущей БД Supabase. Обещание
работы вообще без задержек не является критерием приёмки.
