# ADR-0023. Резервная почта менеджера по франшизе

## Решение

Храним резервный адрес отдельно от учётных данных Supabase Auth. Администратор
указывает UUID существующего менеджера и согласованный адрес. Менеджер запрашивает
письмо из кабинета после повторного ввода текущего пароля. Подтверждение из письма
обновляет только отметку о владении ящиком. Обычный пароль, логин, назначения и
уже открытые сеансы сохраняются.

При потере данных можно указать логин или подтверждённую почту. Сервис отвечает
одинаково и отправляет письмо только на заранее подтверждённый адрес. Письмо
для сброса содержит действующий логин и одноразовую ссылку. Установка нового
пароля проверяет назначение менеджера, назначение ссылки, срок и состояние
учётной записи. После сохранения прежние сеансы и незавершённые токены Auth
отзываются. Для получения доступа пользователь входит обычным способом.

Связь операторской настройки с UUID позволяет сохранить вход по телефону и
восстановить забытый логин. Публичный Supabase Auth продолжает обслуживать
обычный вход. Письма отправляет ограниченное задание systemd на существующем
VPS. Рабочему отправителю нужны только две функции почтовой очереди. Секрет
SMTP и исходный токен не записываются в БД или журнал. Восстановление из копии
требует заново подтвердить резервный адрес. Незавершённые задания очищаются.

## Включение

До настройки отправителя список доступных адресов пуст. Подтверждение адреса
и право сброса включаются отдельно. Право сброса по умолчанию выключено.
Для профиля с подтверждённым вторым фактором используется административное
восстановление. При подключении почты на рабочем профиле проверяют привязку и
прежний вход в отдельном окне. Право сброса включают после проверки на отдельной
учётной записи и на закреплённой версии GoTrue. Удаление ранее существовавших
сеансов и вход, начатый со старым паролем до смены, проверяются отдельно.
