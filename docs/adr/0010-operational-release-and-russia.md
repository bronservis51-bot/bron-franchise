# ADR-0010 Личные доступы, рабочий контур и подготовка локализации

Статус: принято для рабочего релиза; перенос в РФ и автоматический МойСклад
ожидают инфраструктуры. Заменяет разрешение на демо-вход из ADR-0003 и допущение
«только синтетические данные» из ADR-0002 для текущего окружения.

## Контекст

Кабинет уже содержит настоящие рабочие данные и получает обращения с отдельного
лендинга. Облачный Supabase был приостановлен. Для продолжения нужны личные
доступы, изоляция партнёров, надёжная запись денег и подготовленный перенос в РФ.
Исторический демо-порядок развёртывания больше не подходит текущей базе.

## Решение

- Личная авторизация без публичного выбора роли и общего пароля; доступ выдаётся
  менеджером/владельцем в своей области. Сервер проверяет действующую Auth-сессию,
  активность пользователя и права, включая уже выпущенные JWT после отзыва.
- Сохраняется командная граница PostgreSQL по ADR-0004. Прямых клиентских записей
  в защищённые таблицы нет. Финансовые команды имеют защиту от повторов и
  конфликтующих старых изменений. Очередь и обновления не теряют ввод пользователя.
- Продажи/себестоимость УК — приватные месячные снимки из read-only МойСклад.
  Партнёры не получают себестоимость. Сбой интеграции не мешает работе точки.
- Целевое направление: совместимый self-hosted Supabase в России с переносом
  Auth/UUID/паролей, данных и файлов. Адаптер клиента и SQL-контракты сохраняются.
  Исходный код может оставаться в GitHub без реальных данных и секретов.
- Контракт анонимного `lead_submit` сохраняется. Переход требует сверки заявок,
  полученных во время переноса и из старых открытых форм.
- Обязательные правила ИИ — корневой `AGENTS.md`, причины решений — ADR,
  предотвращение повторных ошибок — `docs/lessons-learned.md`, эксплуатация —
  runbooks. Один документ не подменяет остальные.

## Последствия и границы

Нужны оплаченная/предоставленная российская площадка, DNS, резервирование,
мониторинг, обновления и отдельный серверный токен МойСклад. Подготовка к переносу
не равна размещению в РФ; статическая публикация не означает подтверждения всех
серверных настроек. Web Storage сессии остаётся ограничением текущего статического
клиента; BFF/cookie, MFA менеджера и прочие усиления требуют отдельного решения и
не объявляются уже выполненными. Абсолютная безопасность не гарантируется.
