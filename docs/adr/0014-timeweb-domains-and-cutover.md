# ADR-0014: оба сайта и совместимый backend на российском VPS

Дата: 04.11.2026. Статус: конфигурация подготовлена; развёртывание и переключение
не выполнены. Уточняет [ADR-0010](0010-operational-release-and-russia.md).

Уточнение от 10.11.2026: [ADR-0021](0021-release-ownership-and-final-cutover.md)
заменяет допущение о бессрочном приёме старых анкет в зарубежную базу после
локализации и вводит обязательную проверку сопровождения до оплаты.

Выбор адресов ниже заменён решением владельца от 10.11.2026:
[ADR-0022](0022-bronservis-domain-and-subdomains.md). Текущие адреса:
`bronservis.ru`, `app.bronservis.ru`, `api.bronservis.ru`; прежние имена оставлены
в этом ADR как история решения, а не инструкция к покупке.

Владелец выбрал `bsfranchise.site` для кабинета, `bsfranchise.ru` для лендинга
и Timeweb как предполагаемого регистратора/площадку. Требуется сохранить данные,
личные доступы, очередь PWA и контракт анкеты отдельного репозитория.

Подготовлено размещение обоих статических сайтов через Caddy и официального
совместимого Supabase в Docker на российском VPS. API — `api.bsfranchise.site`.
PostgreSQL/pooler/gateway слушают loopback, Studio наружу не проксируется.
Код и CI остаются в GitHub. Покупка услуг/бюджет не подразумеваются этим ADR.

Supabase Docker фиксируется на конкретном commit; текущий upstream использует
Envoy (`api-gw`) и PostgreSQL 17. Обновления стека требуют новой проверки. Caddy
и объединённый Compose проверяются до запуска; синтаксическая проверка не является
пробным восстановлением и не доказывает доступность Docker-образов на сервере.

Финальный перенос проходит через отдельную изолированную цель и полную сверку.
Старый кабинет остаётся доступным для сохранения/отправки своей origin-очереди;
переадресация не может молча потерять её. Старые открытые анкеты требуют проверенного
моста поздних лидов. Подготовлен повторяемый перенос недостающих UUID без
перезаписи целевых карточек; [порядок](../runbooks/late-leads.md).
Пока мост не развёрнут и репетиция не пройдена, переключение запрещено.
Откат учитывает новые записи целевой базы, а не только DNS.

Один VPS — единая точка отказа. Копии вне VPS, проверка восстановления и мониторинг
настраиваются отдельно. Инструкция: [deploy/timeweb](../../deploy/timeweb/README.md).
