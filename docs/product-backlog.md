# Продуктовый backlog

Актуализирован по решениям владельца 15–16 ноября 2026. Перед работой ИИ
показывает ссылку на этот файл. Публичный релиз принят: заявка с лендинга и
создание франчайзи проверены владельцем. Этот backlog не переоткрывает миграцию.

## Ближайший полезный выпуск

| Задача | Критерий приёмки | Состояние |
| --- | --- | --- |
| Дневная мотивация | Сотрудник вводит выручку смены, видит начисление и сумму месяца; прошлые месяцы доступны | В работе |
| Тариф по фото | 16/17/18/19/19/20/21% по порогам 0/8/10/13/16/19/23 тыс. RUB, премии 0/0/0/0/200/200/300 RUB | В работе |
| Сохранение стандартного режима | Гарантированный минимум и процент не складываются; фиксированный выход + процент — отдельный режим | Сохраняется |
| Стажёр | Минимум 500 RUB и та же процентная сетка; настройки применяются явно и не переписывают историю | В работе |
| Исправление своей выручки | Сервер разрешает 5 минут от первоначальной сдачи, пишет историю изменения; повторы не удваивают выручку/зарплату | В работе |
| Доступы команды | Франчайзи создаёт, блокирует, восстанавливает доступ и назначает управляющего; чужие точки/партнёры недоступны | В работе |
| Ротации и управляющий | Можно назначить несколько точек без графика 2/2; управляющий видит разрешённую выручку и заказы | В работе |
| Подготовка франчайзи | «Договор заключён», «Поиск локации», «Подготовка к открытию» доступны без обязательной линейной последовательности | В работе |
| Экономика франшиз | Выручка, расходы, роялти и поставки различимы; нет выдуманной консолидированной прибыли УК | Проверка существующего экрана |
| Простой вход | Бренд, назначение, форма и необходимая помощь; действующий вход и восстановление сохраняются | В работе |
| Историческая выручка | Импорт только подтверждённых дней/точки/валюты, без выдуманной разбивки и без перезаписи конфликта | Ждёт подтверждения реквизитов импорта |

Процент начисляется на выручку за день/смену, не на месячную сумму и не на
введённую вручную зарплату. Нижняя граница каждого нового диапазона включена.
Обычный минимум остаётся действующим (1000 RUB), пока владелец его не изменит.
Политика сохраняется в смене: новая сетка не пересчитывает закрытые смены.
День определяется часовым поясом точки. Пустой отчёт не равен нулевой выручке.

## Правила, которые ещё нужно решить с владельцем

| ID | Вопрос | До решения |
| --- | --- | --- |
| PAY-01 | Два и более сотрудника за одной кассой: общая/личная выручка, разделение процентов и премии, пересечение смен | Не делить кассу автоматически и не начислять каждому процент от общей кассы. Сохранять отдельные отчёты; не обещать утверждённого совместного расчёта |
| PAY-02 | Нужен ли настоящий месячный оклад с пропорциональностью по выходам/норме? | Использовать существующий отдельный фикс за смену + процент; месячный оклад не изобретать |
| PAY-03 | Один сотрудник работает на двух точках за день: общий минимум или минимум каждой смены? | Сохранить действующее начисление за отдельную смену; дневной предел и распределение не придумывать |
| ACCESS-01 | Самостоятельная установка пароля по приглашению и канал доставки | Работает создание/сброс франчайзи и личная смена пароля; не обещать email на служебный логин |
| REV-01 | Год, валюта и конкретная точка исторической таблицы; конфликт с уже внесённым днём | Импортировать только после однозначной привязки; пустые дни и чужие записи сохранять |

## После начала работы сотрудников

- Уведомления об отсутствующем отчёте и согласовании позднего исправления.
- Удобная история изменений доступов для франчайзи, если серверный аудит уже
  сохраняется, но нет отдельного экрана.
- Расширенные пользовательские роли — только по повторяющимся реальным задачам.
- Развитие аналитики после проверки полноты исходных отчётов, без нового
  бухгалтерского контура.
- Дополнительная автоматизация поставок и интеграций по подтверждённой потребности.

## Ограничения выпуска

Нет повторной миграции, чтений закрытого Source, reset/seed рабочей базы,
сброса старых аккаунтов ради импорта, удаления очереди PWA или истории.
Новые функции проверяются по затронутым расчётам/правам; ранее доказанные
backup/restore/Telegram не повторяются без соответствующего изменения.
Пароли пользователей не извлекаются из bcrypt-хешей. Выдача новых паролей —
отдельное действие с отзывом сессий и закрытой передачей владельцу.
