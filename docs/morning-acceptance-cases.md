# Приёмка утреннего обновления

Основание: уточнения владельца 16.11.2026 (МСК), две приложенные таблицы.
Проверки относятся к новым правилам продукта. Миграция из Source, cold restore,
Telegram и принятые сценарии «заявка с лендинга» / «создание франчайзи» повторно
не открываются. Production остаётся публичным; Source остаётся INACTIVE.

## Что требуется до использования новых функций

| ID | Проверка | Ожидаемый результат |
| --- | --- | --- |
| PAY-01 | Сотрудник открывает смену, вводит наличные и карту, закрывает | Выручка = наличные + карта; начисление считается сразу; начисление и выручка попадают в свои месячные итоги ровно один раз |
| PAY-02 | Новая политика по фото; выручка на границах ниже | Вся касса смены умножается на процент достигнутой ступени; это не прогрессивный расчёт отдельных частей выручки |
| PAY-03 | Стандартный режим с минимумом, затем отдельный фиксированный режим | Стандарт: `max(минимум, процент) + премия`; индивидуальный фикс: `фикс + процент`. Минимум не прибавляется к проценту в стандартном режиме |
| PAY-04 | Стажёр с минимумом 500 ₽, та же шкала | При 0 ₽/3 125 ₽ выручки начисление 500 ₽; при 8 000 ₽ — 1 360 ₽. Должность сама по себе не должна менять уже закрытую смену |
| PAY-05 | Франчайзи меняет ставки после открытия смены | Открытая смена использует сохранённые условия; закрытая история не пересчитывается. Следующая смена получает новую политику |
| PAY-06 | Переключение месяца и возврат назад | Видны свои сохранённые смены, выручка и начисления выбранного месяца; чужая зарплата не появляется |
| REV-01 | Не введён отчёт / введён подтверждённый 0 / выходной без открытой смены | Три разных состояния. Пропуск не становится 0, автоматически оплаченная смена не создаётся |
| REV-02 | Исправление на 4:59, затем через 5:00 после первой сдачи | Первая поправка разрешена; на/после 5:00 сотруднику отказано по серверному времени. Исправление не продлевает срок |
| REV-03 | Поправка сотрудника | Сохранены автор, исходные и новые суммы, момент изменения; первоначальное закрытие смены не меняется; начисление пересчитано один раз |
| REV-04 | Старый revision / повтор того же operation UUID / тот же UUID с другим payload | Старый revision отклонён; точный повтор возвращает прежний результат; иной payload не применяется |
| REV-05 | Связь пропала при закрытии/исправлении | «Ожидает отправки» отделено от сохранённого на сервере. Просроченное исправление не обходит 5 минут после восстановления связи; очередь не удаляется молча |
| REV-06 | Франчайзи уже объявил итог дня, затем сотрудник сдаёт смену | Выручка точки не задваивается; итог дня согласуется со сменами, а не складывается повторно с ними |
| ACC-01 | Франчайзи создаёт сотрудника, назначает несколько своих точек | Новый индивидуальный вход работает; можно выбирать разрешённую точку без графика 2/2; чужая точка недоступна |
| ACC-02 | Франчайзи назначает управляющего | Появляются сотрудники, выручка разрешённых точек и заказы. Управляющий не становится менеджером сети и не выдаёт себе/другому управляющему более высокую роль |
| ACC-03 | Управляющий читает/меняет данные за пределами назначений | Серверный отказ, даже при прямом RPC; зарплаты/доступы чужого франчайзи не выдаются |
| ACC-04 | Блокировка / смена пароля / восстановление сотрудника | Старая сессия отозвана; новый вход возможен только при действующем доступе. История и открытая смена не исчезают |
| ACC-05 | Перевод сотрудника на другую точку | Новые смены ограничены новыми назначениями; прежняя история сохраняется. Незавершённая смена явно разрешается руководителем, не теряется |
| ORG-01 | Этапы «Договор заключён», «Поиск локации», «Подготовка к открытию» | Сохраняются/отображаются в карточке и списке; доступны без принудительной очередности. Рабочий active/blocked и доступы не подменяются этапом подготовки |
| ECO-01 | Открыть «Экономика» | Только показатели франшиз: выручка, расходы/начисления и роялти имеют разные подписи; смешанные валюты не суммируются как одна. Неполный остаток не назван подтверждённой чистой прибылью |
| UI-01 | Телефон, PWA, desktop | Вход без каталога возможностей; рабочие поля/кнопки не обрезаются; незавершённый ввод и очередь переживают обновление |

## Контрольные суммы зарплаты

Граница включается в следующую ступень. Значения в рублях, округление до копейки.
Обычный минимум **1 000 ₽ здесь указан как существующий**, а не новое решение
владельца. Если он изменяется, требуются подтверждённые условия; шкала по фото
сама не задаёт этот минимум.

без смены нельзя. Начислено не означает выплачено.

## Доступы для выдачи

TXT с логинами может быть только закрытым файлом владельца, не git/build/chat.
Исходный пароль не восстанавливается из хеша. При отсутствии прежнего закрытого
листка выдачи нужна отдельная согласованная смена пароля конкретного сотрудника,
с отзывом сессий; никаких общих паролей, удаления пользователей или массового reset.
Серверные ключи, S3/AGE/БД/Telegram не входят в список входов сотрудников.

## Отложено без блокировки принятого релиза

- Распределение общей кассы и премий между несколькими сотрудниками на одной
  точке/в одном дне: правило владельцем не задано. Не суммировать одну кассу дважды.
- Минимум при нескольких сменах одного человека на разных точках в один день:
  существующая модель — за смену; дневной общий предел/распределение не выдумывать.
- Жёсткие графики 2/2, универсальный конструктор RBAC, новый почтовый сервис,
  учёт зарплатных выплат/налогов и полный бухгалтерский учёт не требуются.
- Любые новые формулы, автоматический перерасчёт прошлых смен и автоисправление
  конфликтующего импорта требуют отдельного подтверждённого правила.
