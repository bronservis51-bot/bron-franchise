# Приёмка исключений перед выпуском

Кандидат из PR №33 проверялся в изолированных браузерных сеансах и базах с синтетическими данными. Сценарии дополняют [основную приёмку](https://github.com/bronservis51-bot/bron-franchise/blob/58ae0de53de5742b0fff89d3630ea2e0f2d74967/docs/qa/2026-11-23-role-and-launch-e2e.md) и опираются на [реестр](../business-rules.md).

## Проверки и исправления

| Ситуация | Проверенный результат |
| --- | --- |
| 3.1–3.5. Полночь, граница месяца и смена ставки | Проверены местная дата на востоке и западе, 5-е и 6-е число и истечение пятиминутного окна. Явный ноль остаётся отчётом и даёт предусмотренное начисление. Отрицательные суммы отклоняются. Поправка принятой смены использует её сохранённые условия. [Проверки границ](../../tests/db/shift_boundaries.test.ts) |
| 3.3 и 4.2. Две одновременные правки | В PostgreSQL 17 проверены оба порядка поправок сотрудника и руководителя и одновременная отправка старой очереди выручки. Сохраняется одна версия, вторая получает конфликт. Старая вкладка может впервые сдать открытую смену. Для изменения закрытой смены нужна версия. [Проверка двух сессий](../../tests/db/shift_concurrency_pg17.py) |
| 2.2–2.4. Выход, смена аккаунта и отзыв | Запоздалый ответ профиля игнорируется после выхода. Вкладки без запоминания устройства сохраняют свои профили. При потере связи остаётся последний подтверждённый профиль, при ответе об отзыве он очищается. Смена точки или аккаунта не позволяет отправить чужую операцию. Финансовый запрос сохраняет сессию автора. [Проверки сессий](../../tests/unit/sessionSignOut.test.tsx) · [Проверки проводок](../../tests/unit/outboxAuth.test.ts) |
| 3.1 и 4.2. Очередь без сети | Записи отправляются по времени сохранения. Список обновляется на месте, временный сбой можно повторить вручную, конфликт остаётся для сверки. Запоздалая ошибка из другой вкладки не возвращает отправленную запись. На маленьком экране до действий можно прокрутить. [Проверки очереди](../../tests/unit/outbox.test.ts) |
| 2.1–2.2. Два менеджера меняют одну точку, карточку или доступ | Старая форма больше не возвращает прежнюю дату открытия, статус или этап. Ввод сохраняется для сверки. Одновременная выдача одному франчайзи создаёт ровно одно активное назначение. Статус договора и доступ видны отдельно. [Проверки карточки и точки](../../tests/db/manager-partner-checked.test.ts) |
| 4.2 и 5.2. Ошибка отчёта, спорная дата, валюты | Форма сверяет свежую отметку выходного. Доступные расхождения видны при сбое одной точки. Сводка показывает рублёвый эквивалент при наличии курса для всех ненулевых валютных сумм. Excel показывает выбранный период. Некорректная сумма в роялти блокирует отправку. |
| 6.2. Ссылка поменялась в открытом диалоге | Перед переходом проверяются текущие права и ссылка магазина. Для изменившейся ссылки нужно новое подтверждение. При снятии прав или удалении адреса переход прекращается. Уже скопированный адрес отзывается в МойСклад. |
| 7.3–7.4. Смена редакции урока и прав | Начатая попытка той же редакции сохраняет вопросы и порог. После выпуска новой редакции старая незавершённая попытка в отчёте остаётся без оценки. Новую редакцию можно пройти отдельно. [Проверки обучения](../../tests/db/continuous_learning.test.ts) |

## Решения владельца

| Ситуация | Сейчас | Предложение и компромисс |
| --- | --- | --- |
| Смена не попала на сервер вовремя | Новую смену сотрудник сдаёт за сегодня или вчера по местному времени точки. Если связь вернулась позже либо точку успели закрыть, отклонённая запись сохраняется на устройстве. Повтор уже принятой операции безопасен. | Оставить срок для сотрудников. Дать руководителю восстановление просроченной записи с причиной и сверкой кассы. Более длинный срок для сотрудников уменьшит число обращений и увеличит риск записи в уже проверенный период. |
| Ставку поменяли между сохранением без сети и первой отправкой | При первой сдаче сервер выбирает условия по дате смены из действующих настроек. После принятия условия закреплены за сменой. | Сохранять версии ставок с датой начала. Тогда условия для запоздалой сдачи определит дата смены. Правило минимума при работе на двух точках учитывается отдельно в PAY-03. [Бэклог оплаты](../product-backlog.md) |
| Приостановка договора, расторжение, последняя точка закрылась | Договор и доступ меняются отдельными действиями. При закрытии последней точки старый чек-лист может снова появиться. Собственную ранее открытую смену можно сдать после переназначения и нового входа в пределах разрешённого периода. | При паузе оставить владельцу чтение истории. При расторжении отзывать доступ после окончательных расчётов и выгрузки документов. После закрытия последней точки показывать «Нет действующих точек» и начинать новую подготовку отдельным действием. Нужно определить сроки и порядок отзыва. |
| Возврат превышает продажи по одному способу оплаты | Отрицательная сумма смены отклоняется. | Учитывать возврат отдельной операцией с исходным чеком. До реализации определить, как он влияет на заработок, роялти и закрытый месяц. |
| Два платежа совпали по сумме и дате | Повтор отправки использует тот же идентификатор. Два отдельных платежа могут иметь одинаковые реквизиты. | Для автоматической защиты от дубля использовать уникальный идентификатор банковской операции. Совпадение суммы и даты подходит для предупреждения о возможном дубле. |
| За один месяц записаны прошлый долг и исправление роялти | Итог за месяц включает ручные проводки. | Согласовать, должен ли ввод целевого начисления корректировать только начисление месяца или общий итог вместе с внесённым прошлым долгом. Для независимой сверки лучше сохранять прошлый долг отдельным показателем. |
| У владельца есть доступ к нескольким партнёрам | Запрос личных финансов выбирает первое назначение франчайзи. | Если один профиль должен вести несколько юрлиц, добавить явный выбор партнёра и использовать его во всех связанных отчётах. Это требует общего правила переключения, чтобы экран и выгрузка не относились к разным юрлицам. |

Прямой бухгалтерский RPC для исторической выручки сохраняет совместимость. Для закрытой записи он допускает правку без версии. Перевод на версионную команду требует инвентаризации внешних клиентов. Текущий интерфейс проверяет версию.
