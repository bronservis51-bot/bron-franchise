# Проверки рабочих сценариев кабинета

Сценарии опираются на [описание продукта](../product-and-operations.md),
[правила роялти и финансов](../overview.md),
[правила закупок](../runbooks/shop-automation.md) и
[правила обучения](../adr/0019-staff-training-and-shift-recovery.md).

| Роль и задача | Дано и действие | Ожидаемый результат | Проверка |
| --- | --- | --- | --- |
| Менеджер дополняет заявку | Анкета автоматически квалифицирована. Менеджер меняет только заметку. | Колонка по анкете и автоматический режим сохраняются. Явное перемещение по-прежнему выбирает нужный статус или ручную колонку. | [Выбор стадии CRM](../../tests/unit/leadStages.test.tsx) |
| Менеджер повторяет создание после потери ответа | Сервер принял заявку, затем её отредактировали, переместили или удалили. Клиент повторяет исходную команду с тем же ключом. | Повтор возвращает актуальное состояние существующей заявки без ещё одной записи. Другие исходные данные с прежним ключом вызывают конфликт. Удалённая карточка не возвращается в активный список. | [Повторы команд CRM](../../tests/db/manual_leads.test.ts) |
| Франчайзи сдаёт итог дня | В поле сначала введена денежная сумма, затем неправильный текст, пустое значение или сумма выше лимита. | Сохранение недоступно. После исправления передаётся актуальная сумма, в том числе явно введённый ноль. | [Форма выручки](../../tests/ui/revenue-input.html) |
| Сотрудник закрывает смену при сбое связи | Итог поставлен в очередь, затем сервер принимает его или сотрудник сохраняет копию и удаляет конфликтную запись. | До снятия записи из очереди повторное закрытие заблокировано. Синхронизация показывает серверное состояние. После подтверждённого удаления доступно новое действие. Сбой чтения очереди виден сотруднику. | [Очередь смен](../../tests/ui/staff-offline-shift.html) |
| Пользователь выходит из кабинета | Есть ожидающая запись, сбой IndexedDB или другая вкладка добавляет запись во время выхода. | Данные очереди сохраняются. При обнаружении записи или ошибке чтения выход приостанавливается и пользователь получает сообщение. | [Выход и сохранность очереди](../../tests/ui/outbox-signout.html) |
| Франчайзи разбирает расходы | У него одна точка и есть общий расход. Он открывает общий отчёт и отчёт по точке. | Общий расход входит только в общий отчёт. Суммы списка, остаток, история и отчёт по точкам учитывают выбранную область. У партнёра без точек доступен общий отчёт. | [Область финансов](../../tests/db/finance_scope.test.ts) |
| Франчайзи повторяет расходы | Открыт отчёт по отдельной точке. Франчайзи хочет перенести расходы предыдущего месяца. | Перенос по всему партнёру доступен в режиме «Все точки». В форме можно выбрать общий расход или отдельную точку, даже если точка одна. | [Фильтр и форма расходов](../../tests/ui/finance-scope.html) |
| Франчайзи проверяет историю роялти | В кабинете есть выручка до месяца начала учёта. Он открывает исторический месяц и месяц начала. | Выручка сохраняется. До начала учёта автоматическое начисление равно нулю. С месяца начала применяется действующая ставка. | [Область финансов](../../tests/db/finance_scope.test.ts) |
| Сотрудник проходит обновлённый урок | Он сдал прошлую редакцию. Редактор публикует новую и проверяет вопросы. | Новая редакция требует прохождения. Результат старой попытки остаётся в истории. | [Непрерывное обучение](../../tests/db/continuous_learning.test.ts) |
| Редактор подтверждает вопросы после публикации | Он проверил прошлый банк и установил, что вопросы подходят новой редакции. | Банк можно подтвердить для опубликованной редакции без правки текста. Сохранение учитывает версию банка. | [Подтверждение вопросов](../../tests/unit/learningEditor.test.tsx) |
| Исполнитель оформляет согласованную поставку | Партнёр принял предложение на 8 и 12 единиц с разными ценами и сроком поставки. | Исполнитель принимает дату из серверной очереди, использует согласованные цены и сохраняет внешний идентификатор в заявке. | [Контракт очереди заказов](../../tests/db/shop.test.ts) |
| Исполнитель проверяет остаток | Для заказа нужен дробный остаток. МойСклад возвращает количество и резервы. | Остаток ровно в размер заказа достаточен. Любой подтверждённый дефицит блокирует оформление, даже если он меньше шага количества заказа. | [Проверка исполнителя](../../tests/unit/shopWorker.test.ts) |

Проверки проходят через компоненты кабинета и применение миграций в локальной
PGlite. Внешние ответы для сценариев закупок и браузерных форм синтетические.
В сценарии финансов fast-check проверяет 32 пары сумм в минимальных денежных
единицах. Его сокращённый контрпример для отчёта по точке — `[1, 1]`. Тест
закупок генерирует подтверждённые остатки ровно на границе заказа и по обе
стороны от неё.

Команды проекта `npm run typecheck`, `npm test`, `npm run gen:contract` и
`npm run build` проверяют типы, тесты, публичный RPC-контракт и сборку. Браузерные
проверки из `tests/ui` запускаются на локальном Vite с вымышленным API.
