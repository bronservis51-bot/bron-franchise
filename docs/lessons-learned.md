# Ошибки и правила против их повторения

Это журнал практических уроков, а не список новых функций. Обязательные правила
для ИИ находятся в [AGENTS.md](../AGENTS.md); причины решений — в [ADR](adr/).
При новом инциденте добавляй причину, предотвращение и способ проверки.

| Случай или риск, выявленный при доработке | Что учитывать дальше | Как проверить |
| --- | --- | --- |
| Бесплатный облачный проект был приостановлен; клиент продолжал открываться | Доступность страницы не означает доступность БД. Keepalive не заменяет рабочий хостинг, мониторинг и копии | Проверить состояние проекта, Auth и API; [runbook](runbooks/supabase-paused.md) |
| Публичный демо-вход и общий пароль оставались в прототипе | Не возвращать их в рабочую систему; регистрация закрыта, у каждого свой доступ | В опубликованной сборке нет выбора ролей/общего пароля; проверить Auth settings |
| Отзыв refresh-сессии сам по себе не отзывает ещё действующий JWT | Проверять активную Auth-сессию и назначения сервером | Старый токен отозванной сессии не читает данные и не исполняет команды |
| Интерфейс можно обойти прямым запросом к API | Ограничения на чужую точку и себестоимость обязательны в БД | Запрос партнёра в чужую область и в manager-only RPC отклоняется |
| Клиент мог сообщать об успехе при ошибке локального хранилища | Подтверждать локальное сохранение только после успешной записи IndexedDB | Сбой записи даёт ошибку, данные остаются доступными для исправления |
| Повтор запроса и старая офлайн-запись могли задвоить операцию или затереть правку | Ключ повтора с проверкой содержимого + ожидаемая версия; конфликт решается явно | Повтор не меняет итог второй раз; устаревшая версия не перезаписывает свежую |
| Выход/обновление приложения могли потерять неотправленное | Не очищать очередь молча, дать скачать записи перед удалением | Ожидающая очередь блокирует опасный выход/обновление |
| Старая вкладка удерживала прежнюю PWA-версию | Проверять опубликованную версию в новой вкладке после закрытия старых; сохранять режим обновления по подтверждению | После закрытия старых вкладок виден новый вход; активная отправка не прерывается |
| На CI часы UTC и московские даты выбрали разные месяцы | Часы SQL и JavaScript тестов согласованы; бизнес-день зависит от точки | Проверки проходят с UTC у родительского процесса и на границе месяца |
| Старые инструкции предлагали seed/reset и называли настоящую систему демо | Команды первого демо-запуска отделены от обновления рабочей базы | README/runbook не предлагают seed для production; применённые миграции неизменны |
| В резервном скрипте было устаревшее имя таблицы файлов; JSON restore не переносит Auth целиком | Экспортировать `partner_document`, завершаться ошибкой при неполных файлах; полный перенос выполнять по отдельной процедуре | Пробное восстановление, UUID/хеши пользователей и контрольные суммы файлов сверены |
| Наличие скрипта МойСклад можно принять за включённую синхронизацию | Показывать время снимка; расписание и токен проверять отдельно; все страницы отчёта обязательны | Ошибка оставляет последний полный снимок; кнопка перечитывания не выдаётся за загрузку API |
| Совпадающие имена не доказывают, что это тот же партнёр | Сопоставлять UUID контрагента по подтверждённым реквизитам; неоднозначное оставлять непривязанным | Видны непривязанные суммы; нет молчаливого объединения |
| Себестоимость поставок и розничная прибыль — разные показатели | МойСклад даёт учёт поставщика; расходы точки и зарплата берутся из других данных | У каждого показателя есть источник, валюта и понятное название |
| Истёкшие запросы подтверждения миграции задержали применение | Не повторять вслепую и не обходить подтверждение другим каналом. Проверить фактическую схему, дать один конкретный проверяемый следующий шаг | Есть независимое подтверждение результата SQL; ожидание не названо выполнением |
| Смена авторизации или базы могла закрыть вход заявкам лендинга | Сохранять отдельный публичный `lead_submit`; при переносе учитывать старые формы | Аноним может отправлять, но не читать; все UUID заявок до/после сверены |

Отдельные предметные ограничения: плёнки поставляются листами; число заготовок
на листе зависит от вида плёнки. Не приравнивать один лист к одному телефону и
не выводить достоверную розничную выручку из количества купленных листов.
