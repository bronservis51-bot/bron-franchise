# Ошибки и правила против их повторения

## 09.11.2026 — повторный таймаут входа

- Успех с одной сети и ACTIVE_HEALTHY не доказывают вход директора/Android.
  Фиксировать таймаут как наблюдение, не утверждать недоказанную блокировку.
- Проверять отдельно Auth и БД. Диагностика доступна без входа, со временем и
  сборкой, без пароля/токена/заявок. У старой отменённой проверки нет права менять UI.
- Контроль доступности требует внешнего расписания, проверки его запуска и
  отдельного наблюдения с целевой сети. Документ не заменяет дежурного/оповещение.
- «Отказ» не корзина. Удаление явно подтверждается и восстанавливается, старая
  вкладка не меняет удалённую заявку, чужая роль не видит корзину.

Это журнал практических уроков, а не список новых функций. Обязательные правила
для ИИ находятся в [AGENTS.md](../AGENTS.md); причины решений — в [ADR](adr/).
При новом инциденте добавляй причину, предотвращение и способ проверки.

| Случай или риск, выявленный при доработке | Что учитывать дальше | Как проверить |
| --- | --- | --- |
| Бесплатный облачный проект был приостановлен; клиент продолжал открываться | Доступность страницы не означает доступность БД. Keepalive не заменяет рабочий хостинг, мониторинг и копии | Проверить состояние проекта, Auth и API; [runbook](runbooks/supabase-paused.md) |
| Публичный демо-вход и общий пароль оставались в прототипе | Не возвращать их в рабочую систему; регистрация закрыта, у каждого свой доступ | В опубликованной сборке нет выбора ролей/общего пароля; проверить Auth settings |
| Отзыв refresh-сессии сам по себе не отзывает ещё действующий JWT | Проверять активную Auth-сессию и назначения сервером | Старый токен отозванной сессии не читает данные и не исполняет команды |
| Интерфейс можно обойти прямым запросом к API | Ограничения на чужую точку и себестоимость обязательны в БД | Запрос партнёра в чужую область и в manager-only RPC отклоняется |
| Клиент мог сообщать об успехе при ошибке локального хранилища | Подтверждать локальное сохранение только после успешной записи IndexedDB | Сбой записи даёт ошибку, данные остаются доступными для исправления |
| Повтор запроса и старая офлайн-запись могли задвоить операцию или затереть правку | Ключ повтора с проверкой содержимого + ожидаемая версия; конфликт решается явно | Повтор не меняет итог второй раз; устаревшая версия не перезаписывает свежую |
| Выход/обновление приложения могли потерять неотправленное | Не очищать очередь молча, дать скачать записи перед удалением | Ожидающая очередь блокирует опасный выход/обновление |
| Старая вкладка удерживала прежнюю PWA-версию | Проверять опубликованную версию в новой вкладке после закрытия старых; сохранять режим обновления по подтверждению | После закрытия старых вкладок виден новый вход; активная отправка не прерывается |
| На CI часы UTC и московские даты выбрали разные месяцы | Часы SQL и JavaScript тестов согласованы; бизнес-день зависит от точки | Проверки проходят с UTC у родительского процесса и на границе месяца |
| Старые инструкции предлагали seed/reset и называли настоящую систему демо | Команды первого демо-запуска отделены от обновления рабочей базы | README/runbook не предлагают seed для production; применённые миграции неизменны |
| В резервном скрипте было устаревшее имя таблицы файлов; JSON restore не переносит Auth целиком | Экспортировать `partner_document`, завершаться ошибкой при неполных файлах; полный перенос выполнять по отдельной процедуре | Пробное восстановление, UUID/хеши пользователей и контрольные суммы файлов сверены |
| Наличие скрипта МойСклад можно принять за включённую синхронизацию | Показывать время снимка; расписание и токен проверять отдельно; все страницы отчёта обязательны | Ошибка оставляет последний полный снимок; кнопка перечитывания не выдаётся за загрузку API |
| Совпадающие имена не доказывают, что это тот же партнёр | Сопоставлять UUID контрагента по подтверждённым реквизитам; неоднозначное оставлять непривязанным | Видны непривязанные суммы; нет молчаливого объединения |
| Себестоимость поставок и розничная прибыль — разные показатели | МойСклад даёт учёт поставщика; расходы точки и зарплата берутся из других данных | У каждого показателя есть источник, валюта и понятное название |
| Истёкшие запросы подтверждения миграции задержали применение | Не повторять вслепую и не обходить подтверждение другим каналом. Проверить фактическую схему, дать один конкретный проверяемый следующий шаг | Есть независимое подтверждение результата SQL; ожидание не названо выполнением |
| Смена авторизации или базы могла закрыть вход заявкам лендинга | Сохранять отдельный публичный `lead_submit`; при переносе учитывать старые формы | Аноним может отправлять, но не читать; все UUID заявок до/после сверены |
| Фоновая ошибка обновления скрывала уже загруженный экран | Оставлять последнее содержимое с явной отметкой; отказ авторизации/прав скрывает его | Сетевой сбой оставляет доску, `forbidden` и `unauthenticated` показывают ошибку |
| Проверка PWA искала только `role="dialog"`, пропуская native `<dialog>` | Учитывать `dialog[open]`, активные команды, очередь и несохранённый ввод | Открытая карточка блокирует установку обновления; Escape не обходит проверку черновика |

Отдельные предметные ограничения: плёнки поставляются листами; число заготовок
на листе зависит от вида плёнки. Не приравнивать один лист к одному телефону и
не выводить достоверную розничную выручку из количества купленных листов.

- Старая PWA на телефоне: кешированный HTML и ожидающий worker удерживали старый вход. Навигация теперь предпочитает сеть; версия проверяется на возврате, перезагрузка защищает ввод и очередь. Проверять не только новый профиль браузера.
- При повторном импорте нельзя запускать старый первичный импорт с удалением выручки/смен. Сравнивать каждый день, проверять месячные суммы и повторяемость дополнения.
- Мобильная колонка `1fr` сохраняет автоматический минимум; вложенная карточка и длинное имя файла могут растянуть всю страницу. Проверять вложенные grid/flex-блоки и фактическую ширину документа, а не только верхний контейнер.
- Поля наследовали 14,5 px, а компактные селекторы CRM — 11–12 px. На iPhone фокус маленького поля может увеличивать visual viewport, после чего всю страницу можно панорамировать. На сенсорных экранах шрифт полей не меньше 16 px; ручной pinch zoom сохраняется. Отдельно проверять обычный фокус/закрытие клавиатуры, `visualViewport.scale`, ширину документа и прокрутку таблиц/канбана; отключение корневого overscroll устраняет движение на границе, но не заменяет проверку переполнения.
- Кнопки в одной flex-строке с заголовком способны оставить тексту ширину одного слова. На телефоне выделять действиям отдельную строку и проверять длинные заголовки.
- Общий `overflow-wrap: anywhere` у кнопок позволял действиям роялти сжаться до одной буквы на строке даже на компьютере. Пустая QA-таблица и проверка только ширины документа этого не обнаружили. Кнопки не сжимаются; действия таблицы имеют естественную ширину и неразрывные подписи. В QA обязательны заполненные общая и помесячная таблицы, несколько валют, desktop-ширины и проверка геометрии кнопок.
- Корпоративный документ может содержать устаревшие условия и фрагменты чужого шаблона. Наличие ссылки не оправдывает перенос таких цифр в действующий регламент; неизвестное остаётся пустым.
- Смена домена не обновляет уже открытую анкету. Для поздних заявок нужен проверенный перенос исходных UUID; повторный вызов `lead_submit` меняет UUID и повторяет дедупликацию. Данные карточек, уже исправленные менеджером на цели, не перезаписываются.
- Зафиксированный upstream не гарантирует актуальные настройки и исправления безопасности каждого образа. Перед переносом проверять changelog, patch-версию PostgreSQL и значение Auth URL; в новом стеке `API_EXTERNAL_URL` включает `/auth/v1`, клиентский URL — без суффикса.
- «Доступно» с учётом ожиданий и остаток всей сети не доказывают возможность отгрузки с основного склада. Для закупок читать выбранный склад, вычитать его резерв и учитывать резерв без склада отдельно; неизвестные значения и пересчёт не превращать в ноль. Проверять неполные страницы и устаревший снимок.
- Отсутствующий товар, открытый заказ поставщику и его статус не устанавливают обещанный срок. Подтверждение поставки хранится отдельно со ссылкой на документ, количеством, датой и автором; после приёмки его нужно уменьшить. Несколько партий нельзя суммировать с датой самой ранней партии.
- Базовая единица, упаковка и число вырезов на листе различаются. Сохранять единицу конкретного UUID; исключения не исправлять массовой заменой. Название и артикул не ключи интеграции, поскольку могут повторяться.
- API МойСклад позволяет резервировать отсутствующий товар. Проверка остатка и запись резерва не гарантируют атомарную продажу последней единицы при других каналах. До проверки общего порядка резервирования отправка корзины называется заявкой; ручное подтверждение документа не выдаётся за автоматическую сверку API.
- Новые приватные таблицы закупок могли выпасть из прежнего жёстко заданного списка резервирования. Копия включает каталог, заявки, события, подтверждения поступлений и ключи повторов; восстановление проверяет пользовательские ссылки, номера и повтор операции после восстановления.
- Датированные бизнес-данные при сверке копий сравниваются в одном часовом поясе. Разный текстовый UTC offset не является изменением события; точное сравнение выполняется после согласования timezone, без округления временных значений.
- Каталог может выглядеть полным при пустых разделах. Проверять опубликованное
  содержание по рабочим сценариям, показывать недостающий ответ и путь обращения.
- Тесты поиска на коротких синтетических текстах не подтверждают релевантность
  реального корпуса. Прогонять рабочие запросы на закрытой восстановленной копии;
  сохранять исходный запрос в журнале, даже если поиск нормализует ё/е.
- Серверная очередь требует проверки стыка SQL и HTTP: версия конфигурации должна
  передаваться исполнителем, а успешный `void` RPC может вернуть пустой ответ.
  Изолированные тесты двух сторон не обнаруживают несовпадение их контрактов.
- Один товар может занимать две строки согласованного заказа: 8 сейчас и 12 позже
  с разными ценами. Сверять набор коммерческих строк, сохраняя количество и цену,
  а не запрещать повтор UUID товара внутри внешнего документа.
- Неопределённый ответ после POST и подтверждённый отказ — разные состояния.
  Сверка не должна создавать документ заново или требовать текущей цены уже
  созданного заказа. Отзыв сессии после потери ответа не разрешает клиенту менять
  исходный ключ повтора.
- Сумма корзины должна соответствовать создаваемому документу. Если интерфейс не
  рассчитывает дополнительный НДС, автоматизация допускает только включённый в
  цену НДС либо его отсутствие; неподдержанные скидки и валютные правила блокируются.
- Новые типы колонок приватной схемы тоже требуют пробного восстановления.
  `uuid[]` нельзя восстанавливать как JSON-строку; проверять заполненные настройки,
  неизменяемый состав заказа, `syncId` и повтор отправки после restore.

## 2026-11-09 — простота и контроль суммы дня

- Итог владельца и смены нельзя складывать как независимые продажи. Итог включает
  смены; способ оплаты неизвестной части не выдумывается (ADR-0016).
- Сравнение 31-дневного месяца с февралём ограничивать концом февраля.
  Нулевой профиль дня недели не должен приводить к делению на ноль в прогнозе.
- Сотрудник после удаления остаётся в расчёте зарплаты за отработанные смены.
  Даже открытая смена сохраняется, а серверная сессия отзывается.
- Скрыть процент заполняемости только CSS недостаточно: убрать из ответа рейтинга.
- Две вкладки разных аккаунтов требуют отдельных ключей сессии и кеша.
- Вопрос из статьи начинается с пустого поля; контекст показывается отдельно.

## 2026-11-09 — роли, клавиатура и условия смены

- Company scope не даёт права менеджера: техническую роль проверять отдельно и
  на клиенте, и в SQL/RLS. Редактор знаний не получает финансы партнёра.
- При расширении JSON ответа брать последнюю версию функции: ранний staff_home
  содержит сводку точки, которую последующая миграция уже убрала для продавца.
- Новые FK приватных таблиц включать в backup/restore. Проверять копию предыдущей
  схемы: отсутствие нового поля — не NULL и не разрешение сменить старую оплату.
- visualViewport.offsetTop нельзя переносить на весь корень: это повторяет
  автоматическую прокрутку Safari. Диалог прокручивает только собственное тело,
  шапка/действия остаются доступны; фокус открытия не перемещает фон.
- innerHeight и visualViewport могут уменьшиться одновременно. Клавиатуру
  определять относительно высоты до фокуса, а не только разностью этих двух чисел.
- Условия оплаты фиксируются в смене при открытии. Дефолт новой формы не должен
  менять контракт старого staff_create или уже начисленную зарплату.

## 09.11.2026 — непрерывное обучение

- Ежедневное напоминание не означает лимит один урок в день. Раздел, посещение,
  чтение, попытка и зачёт должны быть раздельными событиями.
- Не выводить имя владельца вместо имени вошедшего сотрудника: scope_name описывает
  область доступа, а full_name — человека.
- Банки вопросов подбираются по содержанию, а не по одинаковому числу на статью.
  Непроверенные видео и старые формы сначала требуют проверки, затем публикации.
- Новые обязательные колонки затрагивают восстановление и в private-схеме:
  вставлять только поля, существовавшие в исходной копии, сохраняя DEFAULT.
- Не менять ожидаемые результаты финансовых проверок ради реализации. Сначала
  проверить реальные поля возврата composite RPC и фактическую сохранённую смену.

## 09.11.2026 — простота запуска и ошибки смен

- Личный курс сотрудника и управление обучением — разные задачи. Владельцу не
  назначать курс автоматически; рабочие вопросы не подменять стратегией компании.
- Не использовать неизменяемое closed_at как версию редактирования суммы. Нужен
  отдельный счётчик, общий для правок сотрудника и руководителя.
- Пустое поле и введённый 0 — разные намерения. Неверный ввод не должен отправлять
  предыдущее корректное значение молча. Нулевой итог требует явного подтверждения.
- Ошибки отмены должны быть видимы и при открытой смене. Старая открытая смена не
  разрешает обход закрытого финансового периода; автоматически закрывать её нулём
  или выдуманным временем нельзя.
