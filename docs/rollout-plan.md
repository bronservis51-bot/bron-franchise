# Следующие шаги после рабочего релиза

Личные доступы, работа смен, выручки, роялти, заявок и финансовые снимки опубликованы.
Это не завершённый перенос инфраструктуры. Приоритет — надёжная эксплуатация и
непрерывное поступление лидов; затем автоматизация и удобство ежедневной работы.

| Порядок | Работа | Что требуется извне | Когда этап завершён |
| --- | --- | --- | --- |
| 1 | Российская площадка, домен, защищённый API, БД/Auth/файлы и резервные копии | Реальный сервер в РФ, доступ к DNS и согласованный бюджет/владелец оплаты | Пробное восстановление прошло, данные и доступы сверены, переключение завершено, лиды поступают, восстановление и мониторинг проверены |
| 2 | Автоматическая загрузка МойСклад на этой площадке | Отдельный API-пользователь/токен с правами только чтения; подтверждение спорных контрагентов | По расписанию обновляются полный текущий и предыдущий месяцы; видны давность и ошибки; посторонние не получают себестоимость |
| 3 | Проверка настроек партнёров и доступов | Проверенные точки, даты открытия, ставки/начало роялти, ссылки заказа; точка нового партнёра | Каждый пилотный владелец входит в свою область, видит верные исходные данные и может закрыть день |
| 4 | Недельный пилот и подключение сети | Несколько владельцев для обычной ежедневной работы и короткой обратной связи | Отчёт и смена понятны без сопровождения; суммы сходятся, главные неудобства исправлены |
| 5 | Развитие по фактической пользе | Приоритеты из пилота | Напоминания, упрощение выдачи коротких логинов и другие улучшения имеют владельца, критерий пользы и отдельную проверку |

Проверку исходных настроек и подготовку пилота можно вести параллельно с сервером;
не наращивать состав собираемых персональных данных, откладывая локализацию.
Покупка сервера/домена не считается согласованной этим документом. Стоимость
нужно сверять с действующим тарифом до оплаты; обещание «всё навсегда бесплатно»
для рабочей системы не используется.

## Площадка в России

Предлагаемый путь — самостоятельно размещённый Supabase на российском сервере.
Так сохраняются PostgreSQL, Auth, RPC, RLS и хранилище; смена на случайную другую
БД сейчас потребовала бы лишней переделки. Это выбранное направление подготовки,
а не утверждение, что целевая площадка уже развёрнута.

Для полного Docker-стека официальная документация указывает минимум 2 CPU,
4 ГБ RAM, 40 ГБ SSD, рекомендует 4 CPU, 8 ГБ+ RAM, 80 ГБ+ SSD. Подбор и цена
зависят от файлов, резервирования и обслуживания. Self-hosting требует обновлений,
наблюдения и ответственного за восстановление; российский IP сам по себе этого
не обеспечивает. Проверять физическое размещение, логи, копии и подрядчиков.

Целевые имена: поддомены компании для кабинета и API. Код можно продолжать хранить
в GitHub без реальных данных и секретов. Рабочий кабинет лучше разместить на той
же российской площадке; GitHub Pages не выбирать постоянной площадкой для
коммерческого кабинета с авторизацией, учитывая ограничения самого сервиса.
Перенос лендинга обсуждается отдельно; его работа и приёмник заявок сохраняются.

По общему правилу ч. 5 ст. 18 закона № 152-ФЗ при сборе персональных данных
граждан РФ перечисленные операции с зарубежными базами не допускаются, кроме
установленных законом исключений. Вопрос относится к обработке и размещению
данных, а не к запрету программного обеспечения Supabase. Переезд — необходимая
часть выбранной схемы; политику обработки, основания, сроки, уведомления и права
доступа проверяют отдельно. Не объявлять соответствие закону по одному факту VPS.

### Переключение без потери данных

1. Развернуть изолированную цель, TLS, закрытый административный доступ и копии.
   Сохранить исходную полную копию БД и файлы в закрытом хранилище.
2. Пробно восстановить по официальной процедуре platform → self-hosted.
   Перенести Auth с UUID и хешами паролей, роли, политики и бизнес-данные;
   файлы — отдельно. Обычный `db:restore` JSON для этого не подходит.
3. Проверить входы и чужие области, отозванные сессии, деньги по каждой валюте,
   заявки и вложения. Выполнить `npm run migration:check`; байты файлов проверить
   отдельно. Старые Auth-токены не переносить как действующие: нужен повторный вход.
4. Подготовить приём новых заявок на целевой стороне и механизм учёта переходных
   записей. `lead_submit` сохраняет формат запроса/ответа. Старые формы могут
   обращаться к прежнему адресу: нужен ограниченный переход с пересылкой либо
   сверкой/дозагрузкой, а не немедленное выключение старого адреса. Этот механизм
   требуется реализовать и проверить; он не заявляется уже готовым.
5. На короткое согласованное окно завершить очереди пользователей и остановить
   новые финансовые записи на источнике; заявки продолжать принимать. Перенести
   финальные изменения, сверить UUID и итоги, переключить конфигурацию кабинета
   и лендинга. Проверить настоящую доставку заявок без фиктивных лидов в очереди.
6. Зафиксировать, где разрешена запись, чтобы не возникло двух независимых баз.
   План отката учитывает новые записи после переключения; простой возврат DNS
   без обратной сверки недопустим. Завершить переход и обработку оставшихся копий
   по принятому порядку хранения данных; не удалять источник до сверки.

Технический чек-лист и стартовый промпт: [production-readiness.md](production-readiness.md).
Копии: [runbooks/backup-restore.md](runbooks/backup-restore.md).

## Что подключает МойСклад

Приложению нужна серверная загрузка отчёта продаж по контрагентам: наши продажи
партнёру за вычетом возвратов, себестоимость этих продаж и валовая прибыль.
Подключение МойСклад в ChatGPT не даёт приложению токен и не включает расписание.
Текущие снимки позволяют смотреть историю; для постоянной работы нужен отдельный
read-only доступ и запуск [загрузчика](runbooks/moysklad.md) на сервере.

Начать с загрузки раз в час текущего месяца и ежедневного обновления предыдущего;
это предлагаемое расписание, пока не действующее. Неоднозначные UUID подтвердить
по карточкам. Наблюдать за последним успешным запуском и сохранением старого снимка
при сбое. Оплаты/долги по поставкам и интеграции касс партнёров — отдельные этапы,
если они понадобятся; отчёт прибыльности их не заменяет.
