# Оплата роялти

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax.

**Цель.** «Главная» показывает пропуски выручки или роялти за прошлый месяц. Платёж ЮKassa привязывается к тому же месяцу в действующем журнале.

**Архитектура.** Серверный RPC возвращает месячное состояние и создаёт одну попытку на франчайзи и месяц. Изолированный серверный процесс связывает попытку с ЮKassa и подтверждает статус через API. Клиент может дождаться прямой ссылки только после нажатия «Оплатить».

**Стек.** TypeScript, React Query, PostgreSQL, Node.js, Vitest, systemd.

**Спецификация.** [Согласовано 26 ноября](../specs/2026-11-26-franchise-procurement-and-royalty-design.md).

## Общие ограничения

- Рабочий запуск запрещён без отдельного согласования. Первый внешний запуск только в тестовом магазине ЮKassa и в отдельной тестовой БД. Секреты на сервере.
- С 1-го числа пропуски прошлого месяца имеют приоритет. Карточка оплаты на «Главной», без уведомления из обработчика сохранения. Срок по 5-е включительно, с 6-го просрочка.
- Роялти берётся из действующего журнала. Рублёвый пилот для явно включённых действующих франчайзи. Одна незавершённая попытка на партнёра и месяц, одна запись журнала на идентификатор подтверждённой оплаты.
