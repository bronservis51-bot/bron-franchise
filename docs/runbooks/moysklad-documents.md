# Первичные документы МойСклад на тестовом стенде

Разделы «Финансы → Закупки» и «Экономика → Закупки и отгрузки» читают отдельный месячный снимок. Приёмки и возвраты поставщикам показываются менеджеру. Франчайзи получает отгрузки и возвраты только после подтверждения привязки на дату документа. До включения автоматического учёта расходов требуется отдельная сверка ОПиУ. Импорт не меняет расходы, оплаты и роялти.

## Проверка на вымышленных данных

В локальном checkout выполнить `npm ci`, `npm run gen:contract`, `npm test -- tests/db/purchase_documents.test.ts tests/unit/moysklad-documents.test.ts` и `npm run build`. Тесты импорта используют подменённый GET, тесты команд — локальную БД. Сторонняя учётная запись для них не требуется.

## Подключение отдельного стенда

1. Выбрать отдельную тестовую базу и тестовый аккаунт МойСклад. Использовать отдельного сотрудника с чтением четырёх видов документов, их позиций, товаров, валют, контрагентов и себестоимости. Подтвердить UUID юридического лица УК и область видимых складов. Импорт ограничен одной подтверждённой организацией.
2. Применить миграции на тестовой базе. Дать отдельному логину PostgreSQL право подключения, USAGE на app_private и EXECUTE на app_private.purchase_documents_store(date,timestamptz,jsonb). Запись выполняет только эта функция. API приложения использует именованные команды и проверку сессии.
3. В закрытом файле службы указать `MOYSKLAD_DOCUMENTS_ORGANIZATION_ID` (UUID юридического лица УК), `MOYSKLAD_DOCUMENTS_READ_TOKEN`, `DOCUMENTS_DATABASE_URL` и при необходимости `BRON_DB_CA_FILE`. Пример профиля лежит в `deploy/timeweb/bron-moysklad-documents.service`. Сервис и таймер устанавливаются отдельно после проверки стенда.
4. Из тестовой установки запустить `node scripts/sync-moysklad-documents.mjs --recent`. Два месячных снимка сохраняются одной транзакцией. Для повторной сверки одного месяца есть `--month=YYYY-MM`. При переносе даты документа через границу проверять оба затронутых месяца. Для внесённых задним числом исправлений за пределами окна обновить соответствующие месяцы отдельно.
5. В «Закупках и отгрузках» проверить UUID в карточке МойСклад, выбрать партнёра, начальную дату и точку только при подтверждённом соответствии. До первой датированной привязки контрагент скрыт от франчайзи. Если дата старой привязки неизвестна, оставить период без привязки. Новое назначение действует с отдельно указанной даты. Если прежняя связь прекратилась, выберите «Снять привязку» и дату прекращения. Документы за промежуток до подтверждения нового владельца видит только менеджер. Прежняя история сохраняется. История не заполняется из текущего справочника сводки.
6. Сверить документ со скидкой и НДС, приёмку, отгрузку, оба возврата, вторую валюту, отмену проведения и пересчёт себестоимости. Вкладки показывают сумму каждого вида документов отдельно. Для проверки чистой суммы вычесть показанные возвраты из соответствующего оборота в той же валюте. Сверить документ с количеством больше единицы и с валютой, отличной от учётной, включая сумму `stock.cost` по строке и валюту её отображения.
7. Проверить вымышленные аккаунты двух партнёров, сотрудника, отозванную сессию, неизвестную привязку и общую покупку без точки. При обрыве, несовпадении суммы или размера коллекции предыдущий успешный снимок остаётся доступен с датой. Повторить чтение после устранения расхождения. После остановки таймера сохранённые данные остаются на стенде.

## Источник и сверка

Сервер читает `demand`, `salesreturn`, `supply`, `purchasereturn` с `applicable=true` и их коллекции позиций. UUID, ревизия и полнота страниц проверяются до записи. После чтения позиций каждого типа загрузчик повторно сверяет набор UUID, даты документов и версии по всему запрошенному окну. При расчёте суммы учитываются количество, исходная цена, скидка и режим НДС. Округление выполняется в конце расчёта строки. Несовпадение с итогом источника останавливает замену снимка. Пустая подтверждённая коллекция убирает отменённые документы. Первый запуск не подтягивает историю старше предыдущего месяца.

Валюта документа берётся из `rate.currency.isoCode`, учётная валюта из валюты с `default=true`. Для отгрузок и возвратов покупателей загрузчик запрашивает `fields=stock` на позициях. Если возврат покупателя без основания не содержит `stock.cost`, отдельное поле `cost` не используется: прежде надо сверить его валюту и сумму на позицию либо единицу по возврату с количеством больше единицы. Неизвестная себестоимость сохраняется пустой, нулевая учитывается как нулевая. Документацию сверили 26 ноября 2026 года. [Позиции и поля stock](https://dev.moysklad.ru/doc/api/remap/1.2/#general-general-rabota-s-poziciyami-dokumentov) · [Валюты](https://dev.moysklad.ru/doc/api/remap/1.2/#dictionaries-currency).
