# Подключение координатора к рабочему серверу

Это отдельная настройка доступа по прямому запросу владельца. Она не изменяет
T63, его pins и serving mode и не должна задерживать утреннее обновление.
Production остаётся публичным, Source INACTIVE. Сначала ACCEPTED/исполнение T63;
настройка доступа может выполняться независимо без смены его checkout.

## Браузер

В этом ChatGPT-чате есть инструкция Browser, но Root не получает ни одного
инструмента расширения: js/list_tabs/get_tab_context/handoff отсутствуют.
Наличие установленного расширения на Mac само по себе не подтверждает
подключение именно этого чата.

Локальному исполнителю: через уже разрешённое управление браузером проверить
расширение ChatGPT и подключить текущий чат координатора к Work с выбранным
Chrome. Использовать существующее расширение/сессию; не переустанавливать, не
подменять другим браузером, не завершать личные сессии, не менять общие permissions.
Если интерфейс требует личное подтверждение/логин/MFA — не делать его за владельца,
сообщить точный экран и продолжить T63. Ничего не копировать из истории браузера.
После подключения передать BROWSER_CONNECTION_UPDATED; Root проверит появление
инструментов и фактическую выбранную вкладку. Это проверка UI-подключения, не
утверждение, что управление уже восстановлено.

не копировать и не передавать. Отпечаток публичного ключа:

`SHA256:5k1PhoCXnd16soz7LwU/5A9ATjhb6LKLwKATsP8gnmk`

Установщик `scripts/install-cloud-ssh-key.py` содержит только публичный ключ.
SHA256: `261df9ed54d223ed25a9861fc20fa75719e8fe7cbe8285534314b5a9446a3302`. Шесть изолированных проверок PASS: установка, сохранение
старых байтов и unique backup, повтор без изменений, права, symlink rejection,
отказ при другом наборе опций того же ключа.

Использовать существующий работающий strict SSH исполнителя. Получить файл из
указанного immutable commit этой access-ветки (не переключать работающий T63
checkout), сверить SHA, затем передать его прямо в python3 -I на VPS через stdin.
Готовая однокомандная форма с теми же публичными байтами:
`docs/runbooks/cloud-ssh-command.txt`. Если у действующего SSH есть собственные
параметры/порт, сохранить их; не заменять SSH настройки и known_hosts.

Ожидается KEY_INSTALLED либо KEY_ALREADY_PRESENT с указанным fingerprint.
Установщик добавляет ровно один ключ с опцией restrict, сохраняет старые ключи
и закрытую before-image, не меняет sshd, firewall, порт, сервер/данные/контейнеры.
При BLOCKED не чинить настройки наугад; вернуть фиксированный code.

HTTP unrestricted, но VPN/прямые TCP grants не настроены. Ключ не исправляет
недоступный транспорт.

Исполнителю достаточно передать только безопасные metadata уже работающего SSH:
фактические host/port, наличие ProxyCommand/ProxyJump (без credential values),

Не открывать новый публичный порт, не отключать firewall/host-key checking, не
включать password login и не вводить новый relay/VPN ради T63.

с pinned server fingerprint, статус SSH_NOT_READY. Отпечаток сервера:

условием публикации уже разрешённого обновления.
