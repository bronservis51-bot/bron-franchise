# Рабочий VPS из Codex Cloud

22.11.2026 подтверждён вход на рабочий VPS под `root` через Tailscale. Прямой
публичный TCP/22 вернул `ECONNREFUSED`. Через `proxy:8088` приватный адрес ответил
OpenSSH. Сохранённый в облаке ключ оказался свёрнут в одну строку. После
восстановления формата OpenSSH и проверки серверного отпечатка `id -u` вернул `0`.

## Проверка доступа

1. Для согласованных административных работ проверь, что Codex Cloud подключён
   к VPN. Используй облачный TCP-прокси `proxy:8088` и HTTP CONNECT до
   приватного Tailscale-адреса рабочего VPS на порту 22. Успешный CONNECT
   подтверждает маршрут. Отдельно проверь SSH-аутентификацию.
2. Прочитай несекретные переменные `PRODUCTION_TAILSCALE_HOST` и
   `PRODUCTION_SSH_KNOWN_HOSTS` из GitHub Actions Environment `production`
   репозитория `bronservis51-bot/bron-franchise`. Закреплённый ED25519-отпечаток VPS
   `SHA256:8KA0F5NRZo8hIn84yT/pSclefFxk8zRg9JzuPuilYh0` сверен через консоль AdminVPS.
3. Используй существующий `BRON_CLOUD_SSH_KEY` только для этого подключения.
   Если ключ хранится в одну строку, выдели заголовок и конец блока
   `OPENSSH PRIVATE KEY`, убери пробелы из тела Base64 и собери файл с переносами
   после заголовка, перед концом блока и в конце файла. Примени `umask 077`,
   проверь импорт через `ssh-keygen -y -f <файл>` с выводом в `/dev/null`, удали
   временный файл после сеанса. Храни секрет в настройках среды.
4. Перед работой выполни `id -u` с `BatchMode=yes`, `IdentitiesOnly=yes`,
   `StrictHostKeyChecking=yes` и отдельным `UserKnownHostsFile`. Ожидается `0`.
   Если проверка не прошла, укажи точный этап. `ECONNREFUSED` на публичном
   адресе, ошибка импорта ключа, несовпадение отпечатка и серверный
   `Permission denied (publickey)` требуют разных действий.

Можно использовать `ncat --proxy proxy:8088 --proxy-type http %h %p` как
`ProxyCommand`, если `ncat` установлен. В этой среде проверен вариант с Python 3,
обычным HTTP CONNECT и пересылкой байтов между SSH и сокетом без изменений.
`known_hosts` должен содержать закреплённую строку именно для приватного адреса.

Автоматический выпуск использует собственный логин `bron-deploy` и фиксированную
команду `bron-release-v1`. Для штатного выпуска используй существующий workflow.
[Инструкция выпуска](timeweb-release-automation.md)

## Chrome

Облачный Chrome позволяет управлять вкладками, открытыми в облачной среде.
Вкладки и входы из профиля Chrome на Mac доступны только при подключении
браузерного расширения к текущему сеансу. Перед действием проверь, какой
браузер сообщает инструмент. Для сетевых и серверных работ используй проверенный
SSH-канал.
