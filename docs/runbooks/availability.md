# Сбой приложения: действия без ИИ

Откройте `help.html` рядом с приложением. Она не требует входа. Сохраните адрес
в закладки. Никому не отправляйте пароль. **Не очищайте данные браузера:** там
может находиться очередь ещё не отправленных сумм.

| Что видно | Что сделать самому | Кто продолжает | Когда исправлено |
| --- | --- | --- | --- |
| Нет ответа / AUTH-NETWORK / TIMEOUT | Проверить связь; один раз сменить сеть; скопировать диагностику | Техник проверяет маршрут, Auth, DNS/TLS и журнал | Обычный вход и заявки на пострадавшей сети |
| Вход отвечает, DATA-* не проходит | Не повторять сумму; сохранить диагностику и копию очереди | Техник: PostgREST/ping, БД, миграции | Данные загрузились без потерянных/двойных записей |
| Неверный логин/пароль | Проверить раскладку и личный логин | Выдавший доступ проверяет запись; сброс по подтверждённому запросу | Вход своим аккаунтом в свою область |
| Сессия истекла | Войти снова, сохранив ожидающие записи | При повторе техник проверяет Auth/session_id | Действующая сессия работает, отозванная — нет |
| Недостаточно прав | Передать действие и свой логин без пароля | Франчайзи проверяет сотрудника; менеджер — владельца/директора | Разрешённые действия работают, чужие данные закрыты |
| Заявки не загрузились | Обновить один раз; ошибка не равна пустому списку | Техник: lead_list и права; менеджер: временный закрытый учёт | Список загрузился, поздние заявки сверены |
| Ожидает отправки / конфликт суммы | Копия очереди; не вводить ту же сумму заново | Руководитель сверяет факт; техник — ключ и версию | Каждая сумма один раз с правильной датой |
| Ошибка после обновления | Кнопка «Обновить приложение»; не стирать локальные данные | Техник возвращает совместимый клиент, проверяет контракты | Работает старая PWA, ввод и очередь сохранены |
| Ошибочное удаление заявки | «Заявки» → «Корзина» → «Восстановить» | Менеджер | Та же заявка в прежней колонке |

## Технический порядок

1. Зафиксировать время, сборку, действие, охват и результаты help.html. Сопоставить
   с Auth/edge/PostgREST logs; не называть провайдера виновным по одному таймауту.
   Отдельно проверить доступ из РФ на реальном пострадавшем устройстве.
2. Проверить [availability](https://github.com/bronservis51-bot/bron-franchise/actions/workflows/availability.yml).
   Зелёная проверка другой сети не закрывает локальный инцидент. При старом
   результате проверить планировщик и Variables.
3. Ошибка релиза: совместимый клиент через новый commit/redeploy. Базу не reset/wipe.
   SQL откат — новой миграцией после копии и проверки восстановления.
4. Paused: supabase-paused.md. Сетевой сбой: подтверждённый российский маршрут,
   сохраняя TLS и авторизацию. Нельзя выдавать общий пароль/пустую замену базы,
   повторять неопределённую финансовую запись через другой адрес.
5. Проверка восстановления: обычный вход и lead_list на пострадавшей сети,
   контракт лендинга без мусорной заявки, очередь, права. Записать время,
   фактическую причину/неопределённость и профилактику.

## Ненастроенная эксплуатация

Продукт: менеджер по франшизе. Технический дежурный, резерв, канал срочного
оповещения и обещанное время реакции пока не назначены. Отдельная рассылка не
включена. Ежедневное резервирование в независимое закрытое хранилище требует
инфраструктуры и ограниченных серверных доступов. Разовая копия не расписание.

## Подготовленный российский шлюз

gateway/ — независимый Node 22 HTTP-сервис без npm-зависимостей. Переменные:
SUPABASE_URL (точный HTTPS origin), SUPABASE_PUBLISHABLE_KEY,
ALLOWED_ORIGINS=https://bronservis51-bot.github.io, PORT=8080.
Docker build из gateway либо node server.mjs. Не передавать secret/service_role.

После размещения проверить TLS, /healthz, Auth, ping, CORS и закрытые маршруты;
получить обычный вход и чтение на пострадавшем Android/сети директора. После
этого VITE_SUPABASE_URL клиента и мониторинга меняется на шлюз, публикуется сборка.
Исходная база/Auth не копируются, ключи/UUID сохраняются. Лендинг сохраняет
старый контракт до отдельного перевода. Шлюз не устраняет отказ исходной БД,
сам требует мониторинга/оплаты и не означает хранение данных в РФ.
