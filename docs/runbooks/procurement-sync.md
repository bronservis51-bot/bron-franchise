# Обновление каталога закупок

Скрипт `node scripts/procurement-sync.mjs` выполняется только на доверенном сервере.
Он читает МойСклад и атомарно заменяет проекцию каталога в закрытой схеме приложения.
Заказы, резервы, приёмки и отгрузки в МойСклад он **не создаёт**. Наличие скрипта
не означает, что он уже настроен или запущен по расписанию.

## Конфигурация

В защищённом окружении сервера задать:

| Переменная | Значение |
| --- | --- |
| `MOYSKLAD_READ_TOKEN` | Отдельный серверный токен только для чтения товаров, модификаций и остатков |
| `DATABASE_URL` | Закрытое подключение к нужной БД приложения |
| `MOYSKLAD_PROCUREMENT_STORE_ID` | Проверенный UUID склада отгрузки франчайзи |
| `MOYSKLAD_PROCUREMENT_FOLDER_IDS` | Явный список разрешённых UUID категорий через запятую |
| `PROCUREMENT_CATALOG_MAP_FILE` | Необязательный путь к закрытой проверенной карте UUID → публичное фото; при первом ограниченном запуске задаётся обязательно |

Пустой список категорий запрещён. Дочерние категории не включаются автоматически:
их UUID также нужно разрешить явно. Перед первым включением сверить категории с
текущими персональными магазинами и назначением товаров. Не использовать склады
розничных точек как общий доступный остаток. Если партнёрам положены разные категории,
единый allowlist допустим только для их общей части; индивидуальные области требуют
отдельной серверной политики до расширения каталога.

Для первого каталога плёнок использовать `PROCUREMENT_CATALOG_MAP_FILE`, чтобы
следующее обновление не расширило выбор автоматически до всей категории. Формат
JSON-файла — массив `{ "product_id": "<UUID МойСклад>", "image_url": "<публичный URL>" }`.
При заданной карте импортируется только пересечение её UUID и разрешённых категорий.
Новые товары внутри категории не добавляются сами. Архивные товары не возвращаются.
Ошибочная, пустая или отсутствующая заданная карта прерывает импорт; перехода к
полной категории нет. Сам файл и исходную таблицу сопоставления хранить вне git,
в защищённой конфигурации сервера. Не удалять эту переменную из окружения без
проверки расширяемой области ассортимента.

Карту составляет ответственный после проверки точного уникального совпадения
`externalCode` МойСклад с UID карточки Tilda и контрольного совпадения названия.
Один артикул или название для связи недостаточны. В текущем варианте допускаются
только HTTPS-изображения `static.tildacdn.com`, без учётных данных и query-параметров.
`image_url: null` разрешён. Загрузчик не ищет соответствия сам и не запрашивает
Tilda с чужой сессией: он сохраняет уже проверенную связь по UUID.

У переменных нет префикса `VITE_`. Токен подключённого в ChatGPT приложения не
становится токеном этого сервера. Скрипт не печатает содержимое каталога, цены,
контакты, заголовки авторизации и сообщения драйвера с параметрами подключения.

## Что считается данными

Каталог читается полностью, страницами по 100 позиций с проверкой количества и
дубликатов UUID. Модификации связываются с родителем по UUID; при наличии активных
модификаций выбираются их конкретные UUID, а агрегирующая карточка родителя не
предлагается к заказу. Названия и артикулы не являются ключами сопоставления.
Единица берётся из основной единицы МойСклад: `Лист`, `шт`, `м` и другие значения
сохраняются без пересчёта через упаковки. Неизвестная единица прерывает импорт.

Текущие отчёты `stock`, `reserve` и `inTransit` читаются по всем складам с
`include=zeroLines&withRecalculate=true`, чтобы не потерять резервы без склада.
В проекцию попадает только выбранный склад. Непривязанный резерв консервативно
вычитается полностью. Количество для ориентировочного разделения заявки:

`max(физический остаток − резерв склада − резерв без склада, 0)`.

`null` при пересчёте и отсутствие физического остатка остаются неизвестными.
Ожидания не добавляются к наличию. Созданный заказ поставщику и `inTransit` сами
по себе не подтверждают срок и коммерческие условия: этот загрузчик не заполняет
подтверждённую будущую поставку. Она требует отдельного проверенного источника
с количеством, датой и UUID заказа поставщику. Подтверждения менеджера хранятся
отдельно в `app_private.procurement_incoming`; полная синхронизация каталога их
не заменяет.

Три отчёта не являются одной транзакцией МойСклад. Даже свежий снимок служит для
выбора и предварительного разделения заявки, а не гарантией резерва. Повторная
проверка и фактическое закрепление товара выполняются в МойСклад при обработке.
МойСклад допускает резерв отсутствующего товара: один POST с `reserve` не защищает
от перепродажи. Для автоматизации записи нужен отдельно проверенный серверный
доступ, единый порядок резервирования всех каналов и контроль конфликтов; такой
автоматический режим здесь не включён.

Закупочные и продажные цены не импортируются. Индивидуальная цена остаётся предметом
предложения конкретному партнёру. URL фото из закрытого API тоже не передаётся в
клиент: используется проверенная карта публичных фото, описанная выше. Без карты
`image_url` равен `null`. Синхронизация МойСклад сохраняет фотографии из карты;
закрытые URL API никогда не подставляются вместо них.

## Свежесть, сбои и проверка

Время снимка — начало чтения. Если сбор занял более пяти минут, загрузчик завершится
ошибкой. SQL скрывает численное «свободно сейчас» у снимка старше 5 минут. Ни
перезапуск, ни ошибка не делают старые данные свежими. Не включать расписание,
пока однократный запуск и контроль времени снимка не проверены.

HTTP-запросы имеют таймаут 30 секунд, не следуют перенаправлениям и повторяются не
более трёх раз только при сетевом сбое, HTTP 429 или 5xx. Максимальная задержка
повтора — 10 секунд. После всех успешных чтений выполняется одна транзакция БД.
Ошибка импорта откатывает замену; последний успешный снимок сохраняется. Оповещение
об ошибках расписания нужно подключить на сервере отдельно.

Проверка без внешних записей: `npx vitest run tests/unit/procurementSync.test.ts`.
Проверка на сервере: запустить команду один раз, сверить UUID склада, ассортимент,
единицы, время и выборочные остатки с МойСклад; проверить недоступность неизвестных
остатков. Нельзя считать этот тест доказательством работы автоматической записи,
личных цен или доставки уведомлений.
