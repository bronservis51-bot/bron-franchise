# Подтверждённые итоги выручки без разбивки по оплате

Это модуль для нового ограниченного target-only пакета, а не самостоятельное
разрешение на запись. Рабочие имя, UUID и суммы хранятся в закрытом вводе VPS,
а не в этом репозитории. Старый Source не опрашивать и не включать.

Не использовать `npm run import:sheets`: исторический `importPartner` удаляет
смены, расходы, роялти и прежнюю выручку, а неизвестную разбивку относит к наличным.
Для действующего партнёра это неприемлемо.

## Условия входа

- Владелец подтвердил год, валюту, одну конкретную точку и то, что суммы являются
  полной выручкой точки за день, включающей смены.
- Точка уже существует и активна. Партнёра, точку, сотрудников и смены импорт не
  создаёт. Неизвестные способы оплаты остаются неизвестными.
- Только явно указанные дни. Пустая ячейка не создаёт нулевую запись.
- Сначала сверить все указанные дни. Совпадающие существующие итоги сохранить без
  изменений; при любой отличающейся существующей записи остановить весь импорт и
  передать число конфликтов. Автоматического замещения, удаления или исправления
  прежних записей нет.
- Для записи используется действующий легитимный контекст приложения. Не
  извлекать JWT/пароль из браузера и не создавать/подделывать сессии для импорта.

## Контракт модуля

`morning-revenue-import.mjs` не содержит CLI, строк подключения, фото или
персональных данных. Параметр `q(sql, params)` возвращает массив строк; на запись
нужен отдельный клиент с уже установленным легитимным контекстом приложения.
Сам модуль не устанавливает claims и не получает доступ к Auth.

Закрытый вход имеет `format=1`, случайный UUID `batchId`, проверенный UUID
`locationId`, `currency`, `year`, `month` и массив
`entries: [{day: "YYYY-MM-DD", totalMinor: "целое число копеек"}]`.
Отсутствующие дни в массив не добавлять.

1. `inspectRevenueImport(q, privateInput)` выполняет только SELECT и возвращает
   закрытый `plan` с `sha256`. План включает версии дней и разрешает только
   `INSERT_MISSING_DAY_TOTALS_ONLY`. В чат — лишь статус, количество новых,
   совпадающих и конфликтующих дней, SHA закрытого плана.
2. Только после разрешения записи закреплённый оператор вызывает
   `applyMissingRevenueTotals(q, privateInput, exactPlanSha256)` один раз.
   Команда блокирует дни по существующему протоколу, повторно проверяет весь
   план, вызывает существующий `revenue_total_set` с устойчивыми UUID операций,
   сверяет результат и фиксирует одну транзакцию. Любая ошибка до COMMIT
   откатывает все записи, audit и квитанции этой транзакции.
3. Итоговая декларация использует `reported_total_minor` / `unallocated_minor`;
   наличные и карта не выдумываются. Существующие смены входят в общий итог
   согласно ADR-0016 и повторно не прибавляются. Заработок сотрудников и условия
   старых смен не меняются.
4. `IMPORT_COMMIT_UNKNOWN` — остановка. Сначала сверить существующие квитанции
   операций и фактические версии дней; повтор не разрешён автоматически.

После успешного COMMIT автоматическое удаление для «отката» запрещено: сотрудник
уже мог внести свою смену. Возврат требует отдельного ограниченного решения по
точным версиям затронутых записей. До COMMIT действует обычный полный ROLLBACK.

## Обычный интерфейс, если оператор работает в действующей сессии

Не переносить токены в скрипт ради пакетной записи. Допустим существующий UI:

1. «Франчайзи» → нужный партнёр → нужная точка → подтверждённый месяц.
   Сверить имя точки, валюту и **все** предоставленные дни до первой записи.
2. В «Выручка по дням» нажать «Все дни месяца», если нужная дата скрыта.
3. Пропускать совпадающие итоги. При отличающемся существующем итоге остановиться
   до каких-либо записей и сообщить только число конфликтов.
4. Для каждого отсутствующего предоставленного дня открыть его и заполнить
   «Вся выручка точки за день», комментарий
   «Импорт подтверждённого итога дня; способ оплаты не указан», затем «Сохранить».
   Ввод — в рублях; `MoneyInput` сам преобразует их в копейки.
5. Продолжать только после серверного подтверждения «Выручка сохранена».
   «Сохранено на устройстве» означает очередь, а не успешный импорт. При очереди,
   сетевой ошибке или конфликте остановить новые вводы и сверить уже записанные
   дни без повторной отправки.
6. После последнего дня повторно открыть месяц и сверить каждый предоставленный
   итог и общий контрольный итог. Пустые дни должны остаться «не внесено»;
   заработок/смены не заполняются по этим историческим итогам.

В отличие от пакетного модуля UI сохраняет каждый день отдельной транзакцией.
При остановке квитанция обязана разделять подтверждённые дни и оставшиеся;
откатывать подтверждённые дни удалением нельзя.

## Проверки

`tests/unit/morningRevenueImport.test.ts` проверяет границы входа, нули и пропуски,
совпадения, конфликт, целевые валюту/точку, даты и SHA плана.
`tests/db/morning_revenue_import.test.ts` в изолированной PGlite доказывает полный
откат уже сделанной первой RPC-записи при сбое второй, отсутствие придуманной
разбивки, неизменность старых смен/зарплаты, повтор без записи и отказ старому SHA.
Seed и удаление тестовых строк относятся только к этому изолированному тесту.
