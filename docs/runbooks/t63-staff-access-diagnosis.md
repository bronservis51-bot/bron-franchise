## Только при staff_list / SQLSTATE 42501 на правильном экране

Клиент превращает любой 42501 в общий forbidden: это может быть технический
EXECUTE/grant между функциями, а не недостаточная роль человека. Отсутствие
назначенных точек само по себе даёт пустой список, не forbidden.

`05f8a3e0be1bb7121f74fddd7becf26617b8ec3ae7422b5dc5ecf9990223315d`. Проверено локально на актуальных миграциях: 9 функций, 11 связей,
0 отсутствующих. Локальная проверка не подтверждает native owners целевого VPS.

Доставить ровно эти закреплённые SQL-байты root:root 0600 в существующий
/root/bron-secrets/t63-morning/staff-catalog-only.sql с SHA readback; не менять
рабочий checkout T63. Через уже работающий strict SSH один запуск на прежнем
закреплённом DB container:

```sh
umask 077
set -C
docker exec -i 51071996d381fbfa6a1b6c530045881a5cee6a8c82ee482d83bbf8b47ccf8117 psql -U supabase_admin -d postgres -X -q -A -t -v ON_ERROR_STOP=1 < /root/bron-secrets/t63-morning/staff-catalog-only.sql > /root/bron-secrets/t63-morning/staff-catalog-only.json
```

Query: REPEATABLE READ READ ONLY, statement_timeout5s, ROLLBACK. Только
pg_proc/pg_roles и has_function_privilege. Нет Auth/business rows, DML, нового
Source снимка или использования исчерпанного ledger. Не запускать второй раз
при ошибке/непонятном результате; сохранить безопасный код.

Отчёт: functions.exists/owner/nativeSuperuser/authenticatedExecute и
edges.callerOwnerCanExecute. Владелец функции — техническая роль БД, не логин
сотрудника. Эти поля допустимы; личные записи/идентификаторы не нужны.

Если все edges=true и staff_list доступен authenticated, гипотеза EXECUTE не
подтверждена. Если есть false — дать точную пару caller/callee и владельцев.
Не делать GRANT всем, не назначать дополнительные роли человеку и не менять
owners без отдельной проверенной правки. Следующее исправление основывается
на фактическом результате; опубликованный пилот остаётся публичным.
