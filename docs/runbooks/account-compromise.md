# Компрометация аккаунта

Исполнитель: Менеджер по франшизе и администратор Supabase.

**Ограничение ущерба (минуты):**
1. В приложении: Франчайзи → карточка франчайзи → «Доступ в кабинет» → «Отозвать». Доступ к данным закрывается при следующем же запросе: права проверяются в базе, а не в токене.
2. Supabase Dashboard → Authentication → Users → пользователь → Sign out / Ban — завершает сессии.

**Восстановление:** менеджер задаёт новый личный пароль значком ключа в «Доступ
в кабинет»; пароль сотрудника меняется в «Сотрудники» → «Пароль». Серверный сброс
пароля отзывает старые сессии. Если назначение было отозвано, вернуть его только
после проверки владельца учётной записи. Новый пароль передать лично, не в git.

**Проверка:** старый токен не читает данные и не исполняет команды, новый вход
работает только в разрешённой области. Проверка активной `auth.sessions` важна:
одного отзыва refresh-токена при ещё действующем JWT недостаточно. Если затронут
аккаунт менеджера, действия по его доступу выполняет администратор; не выдавать
роль менеджера через обычную форму партнёра.

**Сверка:** журнал `audit_event` за период — что вносилось и исправлялось от имени пользователя (выручка, оплаты).
