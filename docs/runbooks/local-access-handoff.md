# Локальный Codex: только доступ и транспорт, затем возврат в ChatGPT

Уточнение владельца от **12.11.2026**: основная миграция продолжается в прежнем
чате. Локальному Codex поручен только ограниченный этап ниже. Он заменяет
прежнее поручение выполнить весь перенос из `local-codex-handoff.md`.

## Результат и пределы

Подготовь с Mac проверенный SSH-доступ к уже оплаченному VPS и read-only доступ
этого VPS к исходному PostgreSQL. Если нужен временный SSH-канал, оставь его
работать независимо от процесса задания Codex. Сохрани короткий безопасный
отчёт в GitHub и **остановись**: дальнейшие операции выполняет агент в ChatGPT.

Не делай дампы, не копируй данные, не запускай контейнеры, миграции, seed/reset,
не меняй Auth, пароли, DNS, HTTPS, firewall, рабочее приложение и лендинг.
Не создавай платные ресурсы, не устанавливай удалённый shell/веб-терминал,
не давай публичный доступ к БД или SSH-ключам. Нужные изменения здесь — ключ
владельца, закрытый временный транспорт, обновление одного helper и проверка
подключения. Остальная архитектура уже выбрана; повторное исследование не нужно.

## Выполнить по порядку

### 1. SSH владельца

Полученный с сети ED25519 ключ сначала сравни с указанным fingerprint; затем
добавляй именно проверенный ключ в `known_hosts`. Не используй
`StrictHostKeyChecking=no`, слепое принятие ключа или удаление несовпадающей
записи. При несовпадении останови вход и перепроверь через доверенную VNC.

Используй подходящий существующий ключ владельца/ssh-agent либо создай отдельный
ED25519 ключ `~/.ssh/bron_adminvps_ed25519`, не перезаписывая файлы. Закрытый ключ
остаётся только на Mac с правами 0600; на VPS добавляется только публичный.
Пароль VPS и при необходимости passphrase владелец вводит лично в скрытый
Terminal. Проверь **второй отдельный SSH-вход ключом**, прежде чем считать доступ
готовым. Не отключай пароль, root, VNC и прежние работающие доступы в этом этапе.

### 2. Закреплённый helper на VPS

Проверь IP сервера, отсутствие `/opt/bron/production-enabled` и отсутствие
контейнеров. Если состояние существенно изменилось, не обходи защиту helper.
Загрузи только этот файл, сначала во временный файл на VPS:

```text
https://raw.githubusercontent.com/bronservis51-bot/bron-franchise/11116d25417ca93ebfabd98f01c01d7a23312d69/deploy/timeweb/source-db-access.py
SHA256: 6b51705679976b6f2c4f1b0412ec9bd3973889e3232e726286553bc0f23b7f23
```

После проверки SHA установи как `/opt/bron/source-db-access.py` с root-владением
и правами 0600. Старый helper ожидаемо имеет SHA
`cb30b24e4aa44083a9b44638eaf2248e17d94f57a28bec63ac39cf1660b3cfd0`;
не заменяй неизвестный изменённый файл без разбора отличий.
Существующие source service/pgpass нельзя молча перезаписывать.

CA уже подготовлен: `/opt/bron/source-ca.crt`,
`/opt/bron/source-ca-bundle.pem`. Первый сертификат получен по официальной ссылке:

```text
https://supabase-downloads.s3-ap-southeast-1.amazonaws.com/prod/ssl/prod-ca-2021.crt
SHA256: 700723581420dd1ac98fd7e9ac529f0ef210eadcaf87fc868a3ad7d114c2f3b7
```

Один раз проверь прямой маршрут:

```sh
python3 /opt/bron/source-db-access.py --check
```

Если он проходит с проверкой сертификата/hostname, временный канал не нужен;
перейди к п.4 без `BRON_SOURCE_TUNNEL_PORT`. При сетевом timeout — п.3.
Ошибки сертификата/идентичности исправляй, не обходи проверку TLS.

### 3. Временный канал с Mac при закрытом прямом маршруте

После проверки SSH-ключа и входа основной SSH-вызов с Mac:

```sh
ssh -nNT -o BatchMode=yes -o StrictHostKeyChecking=yes \
  -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 \
  -o ServerAliveCountMax=3 \
  -R 127.0.0.1:15432:aws-1-us-west-2.pooler.supabase.com:5432 \
  root@152.228.115.115
```

При необходимости явно укажи проверенный ключ через `-i`/`IdentitiesOnly=yes`.
Не меняй глобальный SSH config ради этого подключения. Проверь политику
forwarding/GatewayPorts до запуска, а затем реальный listener на VPS:
**только `127.0.0.1:15432`**, никаких `0.0.0.0`, `::` или публичного порта.
Не перенастраивай firewall/SSHD для обхода запрета; сообщи реальный блокер.

Канал должен пережить окончание задания Codex. Используй отдельное окно Terminal
или отдельный управляемый временный процесс; при необходимости простой wrapper
на штатном SSH с восстановлением после разрыва. Не оставляй его только дочерним
процессом tool-вызова и не устанавливай новый платный сервис/дополнительный хост.
На время работы удерживай Mac бодрствующим через `caffeinate -i`. Не меняй системные
настройки сна постоянно. Оставь владельцу понятное окно/команду остановки и запуска.
Отдельно проверь, что канал доступен после завершения остальных команд.
`caffeinate -i` не защищает от закрытия крышки или потери сети: Mac должен остаться
с открытой крышкой, питанием и интернетом. После разрыва проверяй TLS/read-only SQL,
а не одно наличие listener.

Mac передаёт зашифрованный PostgreSQL трафик: пароль БД и выгрузки на нём не
сохраняются. TLS проходит до Supabase с canonical hostname и проверенным CA.

### 4. Подтверждение read-only подключения

Для канала выполняй на VPS:

```sh
BRON_SOURCE_TUNNEL_PORT=15432 python3 /opt/bron/source-db-access.py --check
BRON_SOURCE_TUNNEL_PORT=15432 python3 /opt/bron/source-db-access.py --connect
```

Для прямого маршрута — те же команды без переменной. `--connect` сам повторяет
защитные проверки, скрыто запрашивает **существующий пароль PostgreSQL в TTY VPS**,
создаёт service/pgpass с правами 0600 в root-каталоге 0700 и делает только запрос
метаданных с `default_transaction_read_only=on`. Организуй личный скрытый ввод
владельцем непосредственно в SSH/VNC TTY; не проси пароль сообщением Codex и не
перехватывай ввод/экран с секретом.

Ожидаемые пути:
`/root/bron-secrets/source.pg_service.conf`, `/root/bron-secrets/source.pgpass`.
Для канала service должен содержать canonical `host`, `hostaddr=127.0.0.1`,
`port=15432`, `sslmode=verify-full`, проверенный `sslrootcert`; пароль сопоставляется
с canonical hostname и портом15432. Не печатай pgpass, реальные URL/пароли,
окружение с секретами, строки Auth или личные данные. Не сбрасывай пароль,
не ослабляй TLS, не включай plaintext и не исправляй ошибки через seed/reset.
Предыдущие количества: 16 users/16 identities/1 bucket/0 objects; отличия сами по
себе не ошибка — сохрани новые фактические количества и версию.

## Точка остановки и возврат

работает, временный канал при необходимости остаётся включённым. **Копия и
миграция ещё не сделаны.** Не начинай их и не подготавливай полный экспорт.

Сохрани только безопасный отчёт в
`docs/runbooks/local-access-result-20261112.md`: время/часовой пояс, SSH fingerprint

read_only, пути и права credential-файлов без содержимого, SHA helper, независимый
способ поддержания канала/остановки/возобновления, статус последней проверки и
реальные блокеры. Добавь безопасную серверную команду повторной проверки с уже
сохранёнными credentials. Не включай локальное имя владельца, секреты или дампы.

Проверь diff и закоммить/отправь **только этот отчёт** в существующую ветку без
force push и чужих файлов. Если push недоступен, выдай один короткий итоговый
отчёт для передачи вместо цепочки промежуточных вопросов. В финале дай SHA/ссылку
и сообщи: «Локальный этап закончен, вернитесь в прежний чат и напишите “готово”.
Mac и канал оставьте включёнными». Не продолжай внешние изменения после передачи.
