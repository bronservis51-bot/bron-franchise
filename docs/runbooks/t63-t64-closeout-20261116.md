# Завершение исполнения T63/T64 — 16 ноября 2026

Основание — последовательные отчёты действующего локального исполнителя и
уточнения владельца. Это решение не является новым серверным пакетом и не
переименовывает PENDING в PASS. Production остаётся публичным, Source INACTIVE.

## Решение

Исполнительская роль T63/T64 закрывается как выполненная установка с явно
оставшимися пунктами пользовательской приёмки. Полная live-приёмка не заявлена.
Три новых профиля — отдельная следующая задача и не удерживают текущую роль.
Новые SSH/SQL/POST, публикация, миграции, backup/restore, чтение токенов и новая
проверка уже подтверждённых пунктов для этого закрытия не требуются.

Сохраняются имеющиеся canonical receipts и совпавшие private local mirrors
0600. Не заменять историю результатом ACCEPTED_ALL, не удалять guard/intent,
не менять публичный режим из-за завершения роли. Если существующие receipts
уже содержат перечисленные PENDING, повторная запись на VPS не нужна.

  выручки без конфликтов; пустые дни не изменены; TLS/API/health checks PASS.
- T64: три новые миграции и публикация, прежний отказ доступа сотрудников
  устранён. Франчайзи видит сотрудников/управляющего, сотрудник — личный расчёт
  и сохранённую смену. Никаких массовых назначений и сбросов паролей.
- Индивидуальная стажировка 1–30 ноября и минимум 500 RUB сохранены штатной
  формой, повторно прочитаны; прежнее начисление закрытой смены, другой сотрудник
  и общая ступенчатая политика сохранены.
- Рейтинг доступен менеджеру в UI; после этого исполнитель открыл production

- Владелец подтвердил PWA после последней публикации на своём телефоне.

## Открытые пункты, сохранённые без повторных прогонов

1. Реальный цикл новой смены на настоящей работе сотрудника. Фиктивные открытие,
   закрытие, выручка или автоматическая приёмка запрещены. Отдельное устройство
   сотрудника не проверено; PWA владельца его не подменяет.
2. Прямой live runtime RPC-отказ рейтинга в действующей сессии франчайзи.
   UI guard останавливает переход до API. Токен не извлекался; новая
   диагностическая публикация и имитация сессии не разрешены этим решением.
   Успешный live RPC менеджера подтверждает допуск менеджера и не является
   проверкой отказа другой роли; отрицательный runtime результат остаётся PENDING.
3. Owner-only файл всех старых паролей не подтверждён: прежний файл содержит
   логины. Недоступный пароль остаётся недоступным, без reset/выгрузки хешей.

Возобновлять точечную приёмку при наличии настоящего рабочего сценария или
разрешённого штатного пути. Новые условия оплаты/аккаунты — в отдельной задаче.

## Подтверждённые формулы и следующий ввод

Базовая стандартная оплата — max(минимум за смену, процент по действующей общей
ступени); минимум 1000 RUB для обычного сотрудника, 500 RUB для стажёра.
Действующее правило премий из ранее подтверждённой сетки сохраняется.
Отдельный вариант — фикс за смену + процент; фикс и процент складываются.
Для этого варианта владелец также назвал 1000/500 RUB по типу сотрудника,
но тип, вариант и ставка для каждого нового человека ещё не назначены.
Месячный оклад, ретропересчёт и изменение общей сетки этим уточнением не заданы.

Для трёх следующих профилей разом получить только недостающие телефоны и
персональные условия: обычный/стажёр, вариант, фикс/ставка при необходимости,
период стажировки. Точки и имена уже сопоставлены; повторная инвентаризация
без причины не нужна. Телефоны — в личном вводе существующей формы или уже
разрешённом закрытом канале; пароли выдаются лично владельцу. В общий чат,
git, технический лог и отчёт значения не попадают. До ввода записи не создавать.
