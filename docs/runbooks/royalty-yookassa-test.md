# Тестирование оплаты роялти

Контур предназначен для отдельного тестового магазина ЮKassa и локальной базы `bron_royalty_test`. Отдельное согласование рабочего запуска требуется после приёмки. Тестовый платёж не списывает деньги. Оплата по ссылке открывается после нажатия «Оплатить», а период передаётся в описании, например «Роялти за ноябрь 2026 года».

## Подготовка

1. Используйте тестовый магазин ЮKassa и тестовые API-реквизиты. Проверьте ShopID в личном кабинете. Не копируйте ключ магазина в чат или репозиторий. Настройки действующих магазинов не участвуют в тесте.
2. На отдельной машине или локальном окружении настройте новый PostgreSQL с базой `bron_royalty_test`, изолированный backend приложения и синтетический профиль действующего франчайзи с валютой RUB. Рабочие записи в тест не переносятся. Примените штатные миграции к тестовой базе. В `app_private.royalty_checkout_pilot` добавьте только тестового партнёра. Для этого сценария запись партнёра и учётная запись должны быть действующими без флага demo.
3. Для процесса выделите пользователя с доступом к тестовой базе и конкретным функциям. Владелец тестовой БД выдаёт `USAGE` на `app_private` и `EXECUTE` на `app_private.royalty_checkout_work(integer)` и `app_private.royalty_checkout_observe(uuid,uuid,text,text,text,date)`. Для браузера используйте обычную тестовую сессию франчайзи.
4. Передайте переменные в защищённом файле окружения или в хранилище секретов окружения.

| Переменная | Назначение |
| --- | --- |
| `BRON_YOOKASSA_MODE=test` | Явно включает выполнение только тестового процесса |
| `BRON_ROYALTY_TEST_DATABASE_URL` | URL локальной БД `bron_royalty_test` |
| `YOOKASSA_TEST_SHOP_ID` | Идентификатор тестового магазина |
| `YOOKASSA_TEST_SECRET` | Секрет тестового магазина с префиксом `test_` |
| `BRON_ROYALTY_TEST_RETURN_URL` | Адрес браузера на localhost с тестовым кабинетом, по умолчанию `http://localhost:5173/` |

Для БД действуют общий порядок настройки TLS и переменные в `scripts/database-config.mjs`. Серверные запросы ЮKassa всегда проверяют TLS. После установки зависимостей запустите `node scripts/royalty-yookassa.mjs` для обработки очереди. Для повторного опроса можно подключить `bron-royalty-test.service` и таймер в выделенной тестовой VM. Этот вариант не требует публичного обработчика HTTP-уведомлений. Процесс подтверждает результат чтением API.

## Приёмка

- Сначала выполните `node --test tests/ops/royalty-yookassa.test.mjs`.
- Заполните выручку тестового франчайзи. После возврата на «Главную» проверьте период, сумму, срок и кнопку.
- Откройте оплату и проверьте описание периода. Используйте только тестовые реквизиты карты из инструкции ЮKassa для сценариев успеха и отказа.
- Вернувшись в кабинет, проверьте журнал и оставшуюся сумму. Повторите опрос и убедитесь, что запись одна. Проверьте незавершённый платёж и отмену. При изменении суммы старую попытку нужно сверить, прежде чем открыть новую.
- При неопределённом результате вызова API процесс повторяет запрос с тем же ключом попытки в пределах срока идемпотентности. Не удаляйте такую попытку и не создавайте другую вручную. После окончания окна сверяйте состояние в тестовом магазине.
