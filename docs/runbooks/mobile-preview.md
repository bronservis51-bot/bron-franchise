# Тестовый кабинет на телефоне

Стенд использует отдельный HTTPS-адрес, код доступа и учебные профили. Он собирается из выбранной версии кабинета. Данные создаёт локальный сервер проекта через собственные миграции и учебные примеры. Рабочие выгрузки и ключи интеграций в пакет не входят. Почтовая отправка, МойСклад и Google Sheets на стенде не подключены.

## Как пользоваться

Откройте [стенд](https://preview.152-228-115-115.sslip.io/) в браузере телефона и введите код доступа. Затем войдите в один из учебных профилей. Пароль учебных профилей выдаётся владельцу вместе с кодом по закрытому каналу.

| Роль | Логин |
| --- | --- |
| Менеджер по франшизе | `fm@demo.example.com` |
| Франчайзи | `alpha.owner@demo.example.com` |
| Управляющий | `+79000000012` |
| Продавец | `+79000000011` |
| Стажёр | `+79000000013` |

Для проверки под другой ролью выйдите из профиля кабинета и войдите снова. Через меню браузера стенд можно добавить на главный экран как «Бронь — тест».

## Как загрузить другую сборку

1. Откройте чистый checkout выбранного коммита с каталогом `deploy/preview`. Выполните `bash deploy/preview/build.sh <полный SHA> <абсолютный путь к пакету>`. Запишите SHA-256 пакета.
2. Передайте пакет на VPS по закреплённому SSH. Запустите `deploy/preview/install.sh <абсолютный путь к пакету> <SHA-256 пакета>` под согласованным административным доступом. Команда проверяет пакет, стартует сервисы стенда и обновляет только адрес стенда.
3. Сверьте `/preview-version.json` после входа. Проверьте, что свежая вкладка без кода не получает ни сборку, ни API. Повторите необходимые действия на тестовом профиле. Для рабочего выпуска используется отдельная команда выпуска Timeweb.

Каждая сборка стартует с исходных учебных данных. Предыдущий тестовый набор остаётся на VPS в каталоге соответствующей версии. Ключ cookie, код доступа и пароль учебных аккаунтов хранятся в закрытом каталоге `/etc/bron-mobile-preview` и сохраняются при обычном обновлении. Сервис базы доступен только локально, и его сетевые разрешения ограничены loopback. Caddy проксирует лишь публичный адрес стенда и проверяет код перед отправкой статики или API.

Тестовый адрес использует отдельный origin на DNS-сервисе sslip.io, пока у `preview.bronservis.ru` нет записи. Для перехода на собственный адрес сначала создаётся DNS-запись. Затем согласованно меняются виртуальный хост Caddy, адрес в настройках кода доступа и адрес API в сборке.
