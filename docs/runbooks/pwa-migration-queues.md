# Очереди PWA при переносе в РФ

Статус 12.11.2026: исправления подготовлены и проверены локально, не опубликованы.
Это дополнение к [порядку переноса](russia-migration.md), не разрешение переключать
рабочих пользователей до полной копии и репетиции.

## Подготовленные исправления

- Чтение/удаление IndexedDB завершается ошибкой при сбое, а не пустым массивом
  или ложным успехом. Выход проверяет очередь и чистит только черновики одной
  readwrite-транзакцией; очередь при выходе не удаляется. При ошибке сессия и кеш
  сохраняются.
- Новые временные ошибки offline/external-unavailable/unauthenticated/maintenance
  допускают повтор с исходными payload, UUID операции и финансовой версией.
  Конфликты, старые неверсионированные команды и прежние строковые lastError без
  подтверждённого кода автоматически не повторяются.
- Перед отправкой проверяется текущий владелец очереди. Захваченный access token
  привязан к одному RPC через Authorization; при смене общего пользователя A→B
  операция A не отправляется с токеном B. Токен не хранится в IndexedDB/логах.
- Подтверждённые ошибки сервера сохраняют классификацию при navigator.offline;
  неизвестный серверный код не объявляется временной сетевой ошибкой.
- Ошибка чтения очереди показывается существующим уведомлением и в диалоге.

Проверены 141 unit test, typecheck, production build и git diff --check;
независимая проверка кода не выявила P0/P1/P2 в этой области. Тест с настоящим
Supabase/PostgREST wrapper и подставным fetch подтвердил captured A → shared B
→ запрос A → следующий обычный RPC B. Реальные устройства/IndexedDB и старая
установленная PWA ещё не проверены; unit tests их не заменяют.

## Оставшиеся блокеры переключения

1. Backend задаётся при сборке. Очереди и черновики блокируют обычное обновление;
   нельзя просто снять этот guard. Старая установка должна получить проверенную
   сборку российского API на том же origin и пути `/bron-franchise/`, затем
   войти тем же UUID. Не ставить redirect и не чистить storage/IndexedDB.
2. Нельзя обещать сохранение ещё не зафиксированного ввода старого JS. Проверить
   закрытие всех старых вкладок/повторное открытие, черновики и уже заблокированные
   старые lastError. Код export/recovery/import подготовлен ниже, но ещё не опубликован
   и не проверен на реальном устройстве; до входа экспорт недоступен.
3. Нужен исполняемый, проверенный freeze источника для CRM/финансов/знаний,
   Auth/Storage, cron и Edge. Одного запрета денежных RPC недостаточно. Точный
   способ блокировки managed Auth/Storage ещё не подтверждён, на источнике ничего
   не применялось. Read-only catalog preflight обнаружил ограничения managed-таблиц.
4. Мост лидов вставляет отсутствующие принятые UUID, но не спасает неотправленные
   старые HTML-формы. Нужны реальные ограниченные подключения и расписание,
   сверка pending=0 после T и работа российского приёмника. Живой приёмник нельзя
   затереть финальным restore. Восстановимость всех уже принятых лидов и сохранение
   ввода в старых открытых формах — разные проверки.

Ни эти исправления, ни локальная сборка не закрывают весь допуск релиза. Сначала
полная SQL/Auth/config/files копия, закрытое восстановление и строгая сверка;
затем репетиция старого устройства с очередью и повторным входом, финальное окно
и проверка директора/франчайзи/сотрудника. Очереди сохранять по UUID, суммы не
перезаписывать без версии и проверки уже принятой операции.

## Подготовленный перенос локальных записей

В профиле доступно «Локальные записи», в том числе при пустой очереди. Копия
`bron-local-work` v1 включает очередь и сохранённые черновики только вошедшего
пользователя; токены, пароли и сессии в копию не включаются. Локальные записи
других пользователей не читаются.
Перед выдачей копии проверяется, что она принимается текущим импортёром.
Ограничения одной копии: 5 МиБ и до 10 000 записей каждого типа. При отказе
исходные локальные данные сохраняются, удаление из очереди не разблокируется.
Запуск скачивания не доказывает сохранение файла: пользователь проверяет файл
до явного удаления уже обработанной конфликтной записи.

На новом адресе пользователь сначала входит прежней учётной записью, затем
выбирает файл и подтверждает добавление показанного количества записей. Проверяются
UUID пользователя/операций, разрешённые команды и поля, финансовые версии,
дубликаты и формат. Старый `bron-pending` экспорт также поддерживается. Импорт
одной транзакцией добавляет только отсутствующие записи; UUID с другим payload
или иной существующий черновик отменяет весь импорт. Текущая локальная
классификация ошибки не заменяется более старой копией. UUID, payload, ожидаемые
версии и старые ошибки не пересоздаются и не исправляются автоматически.

После добавления обычная очередь отправляется при наличии связи; сервер повторно
проверяет пользователя, область, ключ операции и финансовую версию. Legacy-команды
без защиты версии и ранее заблокированные ошибки остаются для ручной сверки.
Импорт сам не выполняет RPC, не удаляет исходную копию и не очищает IndexedDB.

Это не закрывает первоначальную доставку обновления: старая установленная PWA с
очередью может заблокировать обычное обновление до появления нового recovery UI.
Guard обновления не ослаблен. До смены origin нужно закончить ввод в старых вкладках
и репетировать их закрытие/новое открытие на прежнем origin и пути с совместимой
сборкой. Пока эта репетиция и браузерная проверка новой формы не пройдены, нельзя
считать перенос локальной очереди проверенным рабочим поведением.

Unit-проверки покрывают отсутствие входа, смену аккаунта во время экспорта,
чужие UUID, сломанные версии/команды/файлы, старый экспорт, повторный импорт,
коллизии, сохранение ошибок и отказ IndexedDB. Для браузерной проверки формы
подготовлена синтетическая сцена
`/tests/ui/responsive-app.html?scene=queue&text=200#/`; все API в ней подставные.
Проверить 320/360/390/430/768/1280/1366/1440/1920 px, обычный и удвоенный текст,
выбор файла с длинным именем, пустую очередь, импорт и конфликты на настоящем
IndexedDB. Локальный headless-браузер в текущей среде не запускается из-за запрета
socket; browser-инструмент из дочернего контекста недоступен. Эта проверка остаётся
открытой, как и реальная старая PWA.
