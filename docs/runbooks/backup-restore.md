# Резервная копия и восстановление

Supabase Free **не делает автоматических резервных копий**. Облачная БД — не бэкап.

## Регулярная копия
- Когда: перед каждой демонстрацией, после значимых изменений данных, минимум раз в неделю пилота.
- `npm run db:export` → `backups/<время>/data.json` (все таблицы приложения). Хранить вне репозитория в корпоративном хранилище с ограниченным доступом: копия содержит все данные стенда.

## Восстановление (проверено тестом tests/db/backup.test.ts)
1. Новый проект Supabase (или проект №2 Free): применить миграции `npm run db:apply` (без `--seed`).
2. Создать пользователей с теми же email: `npm run seed:users` (или консоль Supabase). Идентификаторы будут новыми — восстановление сопоставит их по email.
3. В `.env.local` указать `DATABASE_URL`/`VITE_SUPABASE_URL`/`SUPABASE_SECRET_KEY` нового проекта.
4. `npm run db:restore -- backups/<время> --confirm-wipe` — бизнес-данные целевого проекта заменяются копией в одной транзакции.
5. Сверка: вход менеджера и франчайзи, выручка точки за месяц, сводка роялти (весь долг) совпадает с данными до сбоя.
6. Переключить сборку на новый проект: обновить `.env.local` и `npm run deploy`.

## Ограничения
- Пароли пользователей не переносятся (их нет в копии) — новые пароли из `seed:users` раздаются заново.
- Цели production RPO ≤ 1 ч / RTO ≤ 4 ч прототипом не обеспечиваются; для production — PITR платного тарифа или собственный PostgreSQL с WAL-архивом.
