# T41: что сделать владельцу с телефона

Сайт и API пока в maintenance. Уже подтверждены restore, Auth/RLS, сборки,
резервирование и мониторинг. Эта личная проверка нужна, чтобы потеря Mac или VPS
не лишила вас возможности восстановить сервер. Она ещё не выполнена.

## 1. Сначала личный доступ — без ключа и новой фразы

1. На **своём телефоне** в новой вкладке откройте
   `https://my.adminvps.ru/login`. Войдите в свой аккаунт и пройдите MFA лично.
2. Найдите существующий сервер: услуга **386078**, IP **152.228.115.115**.
   Из его карточки заново откройте управление и консоль/VNC. Точные названия
   кнопок в текущем интерфейсе не подтверждены; используйте ссылку из карточки,
   не старую console-ссылку с Mac.
3. Нужен Linux root-терминал этого сервера, а не пустая страница
   «Неразрешенный». Если требуется Linux login, используйте существующие личные
   реквизиты root, вводя пароль только на телефоне. Не сбрасывайте пароль,
   не перезагружайте и не переустанавливайте сервер.
4. Если консоль снова не открылась, передайте только **домен и этап сбоя**:
   например, «в аккаунт вошёл, консоль из карточки пишет Неразрешенный».
   Полную VNC-ссылку, MFA, пароль и секретный скриншот не присылайте.
5. В отдельной вкладке телефона лично войдите в существующий Timeweb Cloud
   (`https://timeweb.cloud/`). Убедитесь, что можете открыть своё S3 и private
   bucket `bron-franchise-backups`. Access/secret keys открывать не нужно.
   Оставьте доступную вкладку: после успешного helper можно проверить наличие
   указанного им объекта **без скачивания** на телефон.

Сообщите только `PHONE_ROOT_READY`, когда настоящий root-терминал доступен.
Это фактический checkpoint, а не запрос повторного разрешения.
Исполнитель сначала доставит закреплённый public code и сверит его SHA.

## 2. Только после закреплённого T41 и готовности исполнителя

Команды вводите **лично в телефонной root-консоли**. Не используйте терминал Mac,
общую управляемую вкладку или SSH исполнителя. Не включайте запись экрана.

Сначала проверка без чтения ключа и без S3-запроса:

```sh
python3 -I /root/bron-secrets/t41-owner-console.py check
```

Продолжайте только при `status: READY`. Затем:

```sh
python3 -I /root/bron-secrets/t41-owner-console.py recover
```

- Придумайте **новую сильную фразу**, отдельную от пароля DMG и аккаунтов.
  Лучше длинная случайная последовательность слов/символов, минимум 20 знаков.
  Для ненадёжной VNC-клавиатуры удобнее латинские строчные буквы и цифры.
- Helper запросит её скрыто дважды. Символы на экране появляться не должны.
  Не вставляйте фразу в shell-команду, чат, форму исполнителя или общий clipboard.
- Сохраните фразу в личной независимой копии, доступной **без VPS и Mac**.
  Проще всего — бумажная копия. Личный менеджер паролей подходит только если эта
  запись не синхронизируется на Mac. Не кладите её в тот же S3/DMG/backup.
- После загрузки helper попросит ввести фразу **из этой сохранённой копии**.
  Он проверит скачанный S3 ciphertext на закреплённой резервной копии прямо
  на VPS. Никакие ключи или backups на телефон либо Mac не скачиваются.
- При `BLOCKED` остановитесь и передайте только `code`/`phase`. Не повторяйте
  `recover`: одноразовый guard сохраняет факт уже начатой попытки.

## 3. Отдельно подтвердить владение и аварийный доступ

Только после crypto `PASS` и действительного личного входа в оба кабинета:

```sh
python3 -I /root/bron-secrets/t41-owner-console.py attest
```

Helper по одному спросит, сохранена ли независимая фраза, выполнен ли личный
вход в AdminVPS/root-консоль и Timeweb с телефона. Ответ `yes` вводите только
если это действительно сделано. Подтверждение `CONFIRMED` связывается с точной
crypto-квитанцией. Исполнитель передаст координатору только безопасные статусы
и SHA; никаких секретов. После этого продолжится подготовленная release window.
