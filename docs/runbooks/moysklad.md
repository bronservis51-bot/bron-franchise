# Поставки из МойСклад

Кабинет читает защищённые месячные снимки. Себестоимость доступна только менеджеру; публичных таблиц с ней нет. Выручка розничных точек и ввод смен работают независимо от МойСклад.

## Загрузка

На доверенном сервере задайте `MOYSKLAD_READ_TOKEN` отдельного пользователя МойСклад с правом чтения отчёта «Прибыльность». Для расписания задайте `TARGET_DATABASE_URL` с доступом к записи снимков через `app_private.supply_store`. Ручной запуск за один месяц использует `DATABASE_URL`. В обоих режимах используйте рабочую базу Timeweb и существующую проверку TLS. Секреты передаются через защищённое окружение, вне git и браузера. Подключение МойСклад в ChatGPT не передаёт приложению его секрет.

`node scripts/sync-moysklad.mjs --month=2026-10` обновляет указанный календарный месяц. Без аргумента загружается текущий месяц по московскому времени. `--recent` обновляет текущий и предыдущий месяцы, чтобы учитывать поздние возвраты и исправления. Каждый месяц записывается отдельно. Если один из них завершился ошибкой, второй всё равно проверяется, а процесс завершается с ненулевым кодом.

Команда загружает все страницы `profit/bycounterparty`, проверяет полноту и уникальность UUID, учитывает возвраты и атомарно заменяет снимок. Ошибка оставляет последнюю успешную версию периода. При одновременных загрузках сохраняется снимок с более поздним временем начала чтения. Заказы и оплаты не прибавляются к отгрузкам. Деньги отчёта — учётные рубли, независимо от валюты розницы партнёра.

## Расписание на сервере

1. Разместите проверенную версию проекта с установленными npm-зависимостями в `/opt/bron/purchase-sync`. Создайте системного пользователя `bron-supply` с доступом на чтение к релизу. В `PATH` службы указан Node 22, закреплённый на VPS. При смене пути Node обновите unit при установке.
2. Запишите `MOYSKLAD_READ_TOKEN` и `TARGET_DATABASE_URL` в `/etc/bron-franchise/moysklad-sync.env` с владельцем `root` и правами `0600`. Проверьте, что база назначения обслуживает «Экономику». Если для подключения требуется отдельный сертификат, укажите `BRON_DB_CA_FILE` с доступом на чтение для службы.
3. Скопируйте [службу](../../deploy/timeweb/bron-moysklad-sync.service) и [таймер](../../deploy/timeweb/bron-moysklad-sync.timer) в `/etc/systemd/system/`. Проверьте `systemd-analyze verify` для обоих файлов и выполните `systemctl daemon-reload`.
4. Выполните `systemctl start bron-moysklad-sync.service`. Проверьте результат обоих периодов через `journalctl -u bron-moysklad-sync.service` и сверьте время снимка и суммы выбранных контрагентов с отчётом МойСклад в «Экономике». Отдельно проверьте непривязанных контрагентов.
5. После сверки выполните `systemctl enable --now bron-moysklad-sync.timer`. Таймер настроен на запуск раз в час. Проверьте ближайший запуск через `systemctl list-timers bron-moysklad-sync.timer`, затем первый результат по расписанию и новый снимок в приложении. Рабочий статус подтверждают результаты запуска и снимок, доступный менеджеру.

## Привязки

UUID контрагента закрепляется за партнёром. В разделе «Экономика» менеджер видит непривязанные суммы и может проверить исходную карточку, затем привязать её. Совпадение одного имени не доказывает личность. Несколько подтверждённых карточек одного партнёра учитываются вместе; сами карточки МойСклад не меняются.

Кнопка «Обновить сводку» перечитывает последний снимок, а не вызывает МойСклад из браузера. Дата загрузки показана явно. Пустой период и отсутствие привязки отображаются как неизвестные данные, а не как нулевые продажи.
