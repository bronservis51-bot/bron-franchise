# Бронь Сервис — кабинет франчайзи

Рабочий кабинет менеджера франшизы, владельцев точек и их сотрудников.
Менеджер видит сеть, планы и выручку, заявки с лендинга, роялти и экономику
поставок. Франчайзи ведёт смены, сотрудников и расходы, видит свой результат и
роялти. Сотрудник закрывает смену и видит начисленный заработок. База знаний
помогает всем ролям. Интерфейс на русском; суммы в валюте точки (₽, ₸, ₺).

Сайт: https://bronservis51-bot.github.io/bron-franchise/

**Сейчас:** статический клиент на GitHub Pages, PostgreSQL/Auth/файлы в зарубежном
Supabase. Личные доступы и финансовая панель опубликованы. Переезд в РФ и
регулярная серверная синхронизация МойСклад ещё не выполнены; финансовая панель
читает загруженные снимки. Подготовленный скрипт не означает действующее расписание.

**В рабочей базе настоящие данные.** Синтетические seed в репозитории предназначены
только для изолированной локальной разработки и отдельного демо-окружения.
Не применять seed/reset/wipe к рабочей базе.

## Быстрый старт для разработки (без облака)

```bash
npm ci
npm test                 # тесты базы на PGlite: права, выручка, план, роялти, база знаний, восстановление; выгрузка в Excel
npm run local:backend    # локальный бэкенд разработки на :54321 (эмуляция Supabase поверх тех же миграций)
```

Во втором терминале создайте `.env.development.local` с `VITE_SUPABASE_URL=http://localhost:54321` и `VITE_SUPABASE_PUBLISHABLE_KEY=local-dev-publishable-key-0000`, затем запустите `npm run dev`. Пароли демо-пользователей — в `local/demo-users.local.md` (этот файл не коммитится).

## Публикация

Обновление существующей системы: [docs/runbooks/deploy.md](docs/runbooks/deploy.md).
Сначала проверки и копия перед изменением БД; только новые миграции без seed,
затем публикация и проверка фактического результата. `main` запускает CI и Pages.

## Команды

| Команда | Что делает |
| --- | --- |
| `npm test` / `npm run typecheck` / `npm run build` | Проверки, типы, сборка |
| `npm run gen:contract` | Обновить типизированный контракт команд из SQL после изменения миграций |
| `npm run db:apply` | Только новые миграции в проверенном целевом окружении; перед рабочими изменениями нужна копия |
| `npm run db:export` | Закрытая копия бизнес-данных, Auth-сведений и вложений; хранить вне git |
| `npm run migration:check` | Сверить источник и цель переноса без записи |
| `npm run sync:moysklad -- --month=YYYY-MM` | Серверная загрузка полного месячного снимка с read-only токеном |

`seed:users`, `db:apply -- --seed`, `db:apply -- --after-users` и `db:reset-demo`
относятся только к отдельному демо. `db:restore -- <каталог> --confirm-wipe`
заменяет бизнес-данные цели; это не полноценный перенос Auth. Сначала прочитайте
[backup-restore.md](docs/runbooks/backup-restore.md).

## Безопасность

- В браузере допустимы URL проекта и publishable/legacy anon key. Серверные секреты,
  выгрузки, документы и пароли пользователей не публикуются в git или сборке.
- RLS защищает таблицы, RPC проверяют роль, область и активную сессию. Клиент
  использует именованные команды вместо прямых записей в защищённые таблицы.
- Франчайзи видит свои точки и роялти. Рейтинг отдельно раскрывает участникам
  предусмотренные им показатели; себестоимость УК доступна только менеджеру.
- Самостоятельная регистрация в Supabase выключена: доступ выдаёт менеджер.
- Анонимный `lead_submit` остаётся доступен лендингу только для приёма заявок.
- Браузерное хранение сессии остаётся ограничением текущего клиента; не считать
  рабочий релиз доказательством абсолютной безопасности или полного соответствия закону.
