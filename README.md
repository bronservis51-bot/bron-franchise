# Бронь Сервис — кабинет франчайзи (прототип)

Минимальное приложение только для франчайзи «Бронь Сервис». У него две функции:

1. **База знаний.** Инструкции, регламенты, ответы на частые вопросы. Обязательные статьи франчайзи подтверждают кнопкой «Ознакомлен».
2. **Выручка и план.** Франчайзи каждый день вносит итог по точке (наличные + карта) и видит, сколько выполнено от плана на месяц. Менеджер по франшизе видит всю сеть, ставит планы и ведёт роялти: 7 % считаются сами, есть сводная таблица долгов по всем франчайзи с выгрузкой в Excel.

Роли: **Франчайзи** (владелец, свои точки и свои сотрудники), **Сотрудник** (смены и свой заработок) и **Менеджер по франшизе** (администратор, вся сеть). Есть рейтинг франчайзи, расчёт плана на месяц и роялти для франчайзи в реальном времени. Интерфейс на русском, суммы — в валюте точки (₽, ₸, ₺). Подробно: [docs/overview.md](docs/overview.md).

Работает за 0 ₽: статический клиент на GitHub Pages и Supabase Free (Auth, PostgreSQL). Сайт: https://bronservis51-bot.github.io/bron-franchise/

> **Демонстрационный стенд.** Только синтетические данные.

> **Происхождение.** Выделено из прототипа корпоративной платформы `bron-platform`. Первый коммит этого репозитория — исходный снимок той платформы, поэтому её код всегда можно найти в истории.

## Быстрый старт для разработки (без облака)

```bash
npm install
npm test                 # тесты базы на PGlite: права, выручка, план, роялти, база знаний, восстановление; выгрузка в Excel
npm run local:backend    # локальный бэкенд разработки на :54321 (эмуляция Supabase поверх тех же миграций)
```

Во втором терминале создайте `.env.development.local` с `VITE_SUPABASE_URL=http://localhost:54321` и `VITE_SUPABASE_PUBLISHABLE_KEY=local-dev-publishable-key-0000`, затем запустите `npm run dev`. Пароли демо-пользователей — в `local/demo-users.local.md` (этот файл не коммитится).

## Публикация

Пошагово: [docs/runbooks/deploy.md](docs/runbooks/deploy.md). Кратко: проект Supabase Free → `.env.local` → `npm run db:apply -- --seed` → `npm run seed:users` → `npm run db:apply -- --after-users` → `git push`.

## Команды

| Команда | Что делает |
| --- | --- |
| `npm test` / `npm run typecheck` / `npm run build` | Проверки, типы, сборка |
| `npm run gen:contract` | Обновить типизированный контракт команд из SQL после изменения миграций |
| `npm run db:apply [-- --seed] [-- --after-users]` | Применить миграции (и демо-данные) к проекту Supabase |
| `npm run seed:users` | Создать демо-пользователей через Admin API (секретный ключ — только в `.env.local`) |
| `npm run db:reset-demo -- --confirm-wipe` | Пересоздать демо-базу с нуля (только демо-проект) |
| `npm run db:export` / `npm run db:restore -- <каталог> --confirm-wipe` | Резервная копия / восстановление |

## Безопасность

- В браузере и репозитории — только URL проекта и publishable key. Секретный ключ и пароль базы хранятся только в `.env.local` администратора.
- RLS включён на всех таблицах. Клиент не пишет в таблицы напрямую: он вызывает только именованные команды, и каждая проверяет права.
- Франчайзи видит только свои точки и не видит роялти.
- Самостоятельная регистрация в Supabase выключена: доступ выдаёт менеджер.
