# Проверка релиза кабинета

Прочитай [AGENTS.md](../../../AGENTS.md) и [порядок выпуска](../../../docs/runbooks/deploy.md).
Публикацию, применение миграций и другие записи в рабочем окружении выполняй по явному поручению.

1. Определи целевое окружение, URL и SHA. Для кода выполни `npm run typecheck`, подходящие
   тесты и `npm run build`. Для `npm run test:e2e` с локальными фикстурами выбирай проекты
   и сценарии по diff и правилам репозитория.
2. Для затронутых прав проверь через API или БД разрешённую роль, чужую область, анонима
   и отозванную сессию. Для денежных операций проверь повтор, конфликт и сбой сети.
   Для изменений входа или приёмника проверь контракт `lead_submit` и запрет анонимного чтения.
3. Сверь фактические результаты CI и публикации для нужного SHA. При изменении RPC выполни
   `npm run gen:contract` и проверь diff. Для изменений БД проверь копию и пробное восстановление.
   Разрешённым чтением сверь имена и контрольные суммы применённых миграций
   в `app_private.schema_migration` на целевой базе. После тайм-аута или истечения подтверждения
   сначала установи состояние операции. На рабочем URL проверяй только разрешённые сценарии.
   Для синтетических лидов, аккаунтов и финансовых записей используй изолированное окружение.

В отчёте укажи SHA и окружение, команды и результаты, ссылки на CI и публикацию, статус миграций,
фактически проверенные рабочие сценарии и оставшиеся пробелы. Отмечай каждый неподтверждённый этап явно.

## Мобильные проверки по diff

- Мобильный интерфейс, вход, заявка или смена → `npm run test:e2e -- --project=mobile-chromium`
  и `npm run test:e2e -- --project=mobile-webkit`.
- Service worker или обновление PWA → `npm run test:e2e -- --project=pwa-chromium`.
  Проверь переход со старой сборки с сохранением сессии, ввода и очереди в режиме приложения Chromium.
- Установка, обновление PWA или очередь → найди прогон нужного SHA в
  [PWA on mobile devices](../../../.github/workflows/pwa-devices.yml). Если прогона нет,
  запусти `gh workflow run pwa-devices.yml --ref <ветка>` после появления workflow в `main`.
  Приложи ссылку и результаты Android Emulator и iOS Simulator по отдельности.
  Физические устройства указывай отдельно, с моделью и версией ОС, если их проверяли.

Для мобильного прогона достаточно SHA, итогов выбранных проектов и статуса устройств. При сбое
укажи упавший шаг и путь к trace или артефакту Appium. Открывай только лог упавшего задания.
Если проверка заблокирована, кратко назови причину и фактический статус.
